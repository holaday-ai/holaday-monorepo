## 股市快照 HTTP 400

前端 `snapshotId/dataAsOf/trustMode` 与 Zod 格式一致。原错误类别为 `SNAPSHOT_NOT_OWNED`，未发现字段名或路由错误。当前用户范围校验正常。本轮只读数据库关联也确认，当前返回快照能匹配同一用户的持久化记录；故障并非每次请求必现。原失败没有逐请求关联记录，不能断言当时只命中下面哪一条路径。

两个可以在实际 `dashboardSnapshot` 路由复现的代码缺陷：

1. 缓存命中时重新校验交易日历。指纹包含交易日历等信任字段，重新校验可以改变 ID/模式，但这一返回版本没有持久化。紧接着 `riskRadar` 按用户持久化快照精确查找，即拒绝。
2. 持久化表按用户/自选列表的缓存键更新一行。后台快照刷新替换了显示缓存，页面刚拿到的上一版本立即消失。

修复：在 API 返回前，把实际返回版本存为独立、用户绑定的短期上下文。沿用已有缓存表的不同哈希键及 `served-stock-context-v1` 包装；无需新表或迁移。重复签发只续期，不覆盖原上下文正文。旧版本保留10分钟；只清理本用户这个新增临时命名空间，当前显示缓存与历史业务记录不在清理范围。校验先精确查该用户及 ID/日期/模式组合，再执行原有日期、信任模式、证据、意图/股票范围校验。兼容当前持久化显示快照的旧校验；过期旧版本不会作为归档上下文使用。存储失败时返回明确服务错误，不成功签发一个不可验证的快照。

## 文件下载 HTTP 404

对前次3条真实文件做只读事务和存储检查：记录存在，属于当前登录用户，`input/active` 且未过期；路径是旧 `/tmp/holaday-files/...` 绝对路径。当前生产提供者为 R2。原本地路径、作为字面R2键的完整路径，以及去掉受信本地根目录后的规范R2对象均未找到。结论：当前存储没有可返回的内容；本次不是路由、文件ID或所有权校验错误。未读取/公开文件正文、账号ID、存储键或凭据。

修复：R2只将受信旧根目录中的合法用户/文件路径映射为规范对象键，使已经迁入R2但保留旧记录路径的对象可读取、HEAD、签名和删除。未知绝对路径、`..`、反斜线等拒绝；不读任意本地路径，不重写数据库路径。真正不存在的对象仍返回404，不能用假内容或成功响应掩盖。权限/网络错误传播为服务故障，不再被当成不存在。

`files.list`保留所有合法元数据、顺序和分页游标，增加 `available/unavailable/unknown` 三态。R2 HEAD检查最多3并发、2秒取消期限，取消后仍等待请求结束；未检查项或超时/权限/网络异常为unknown。文件页面接收confirmed-unavailable后，在缩略图、预览和引用前使用现有失效保护。

**数据恢复限制：上述3条文件在当前主机与当前R2中都没有内容，代码兼容与可用性修复不能恢复原文件。要恢复下载200，需要找到备份或原文件；本次没有伪造、删除、重分类或改写历史记录，也没有运行迁移。为何原临时文件消失，缺历史事件证据，本次不猜测重启/清理原因。**
