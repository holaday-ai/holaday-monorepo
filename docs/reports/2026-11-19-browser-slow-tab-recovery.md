# 慢页面准备超时后的同页恢复

独立任务页已创建、但加载超过八秒时，旧准备逻辑会缓存失败的 Promise。页面随后加载完成，原准备编号仍立即返回失败。单元用例先复现该行为，再修复；没有延长准备期限。

同一 worker 收到原准备编号后，只重新观察已知页面。并发查询共用观察结果，创建、导航和焦点切换不会重发；页面离开授权站点或读取期间账号变化时拒绝返回句柄。创建结果未知时继续保留拒绝，旧条目清理也保留未确认的创建记录；该过期保留边界另有失败到通过的回归。

相关四文件最终 104 项通过，覆盖准备、实际工具协议、会话和持久化准备协议。定向严格类型和三文件静态检查通过。测试运行器最初的条件分支错误已纠正，该次未启动测试，不计入测试失败或产品验证。

真正 Chrome 使用全新空白配置及实际构建的 QA 插件，合成网页故意保持响应未完成。首次准备失败后才完成响应，再用同一准备编号取得原页面，后续查询返回同一结果。合成源页面共两次请求（原页一次、任务页一次），任务页只创建一张，原页输入、用户页输入和活动标签页均保留。该验证只使用本机页面与合成身份，浏览器和自有配置已清理；模型调用和站点原件导出均为零。

此修复覆盖同一 worker 的既有准备记录。实际站点完整任务、真实耗时和跨进程账号生命周期仍需继续验收；草稿 PR 保持未合并、未上线。
