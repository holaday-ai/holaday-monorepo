# Goal2：云端身份与会话连续性候选

本阶段沿用已有 Home、F1/F2、Session Vault、SqlVaultStore 和 KeyProvider，补实际 SQL／原生浏览器证据与恢复后的账号主体核验。生产开关未修改，未合并或部署。

## 已有能力与本次改动

F1/F2 已有授权、加密快照、保存/恢复、UI 和撤销机制；SQL 有所有者锁、版本 CAS、租约、过期和关闭账号检查。Home 已有单任务借用、归还及原始文件归属。本阶段没有重复建立这些能力。

新增私有 v2 快照，将站点稳定主体和会话状态一起放入既有 AEAD 加密内容，沿用 owner/origin/grant/purpose/version 上下文。主体不进入公开 metadata 或明文 SQL。旧快照可读，但没有主体证明时不进入自动执行。

可信站点适配器由服务端配置只读路径、登录标记及稳定主体读取规则。主体证明是内存中的不可序列化回执，绑定原授权、快照版本和实际状态摘要。cookie-only 站点也可证明主体，不要求 localStorage 存账号。

真实 executor 承载会话核验器。统一执行入口在首次模型调用、各模型角色、动作派发、完成判断前核验。未知主体、账号变化、页面失效或授权无法确认时，关闭受影响会话、丢弃未确认写回并等待用户核对已完成步骤。不会自动重放已生效操作。

任务及 Home 中的临时只读核验 context 与主会话共享浏览器进程，独立管理生命周期，不切换用户页面。迟到旧核验不能中断替换后的新核验器；断开会等待临时 context 的取得和实际关闭，关闭失败继续保留资源状态。F1 导入校验沿用独立的 worker context 工厂。

## 生产接线及真实账号待验清单

当前 `application-main.ts` 创建 Vault 时没有传入 KeyProvider 或可信 probe；启用依赖 Vault 的开关会拒绝启动。`CloudKmsKeyProvider` 是可复用的供应商接口接缝，尚不是选定云账号的配置。仅检查过本地部署配置的变量名，未证明远端云账号没有 KMS。

| 需要的输入或操作 | 执行方式与验收 |
| --- | --- |
| 已有 KMS 的供应商、region 和 key alias/id | 用户给非敏感标识；执行者复用现有凭据/身份接线，不在聊天收集密钥、不新购或充值。验证生成/解封、错误拒绝及新 Node 进程可解封同一密文；权限最小化并记录轮换/回滚。KMS 问题仍待用户答复。 |
| 选定真实站点及授权测试账号 | 确认准确 origin、允许用途和账号范围。用户自行处理登录/验证码，执行者不保存密码。 |
| 可信只读主体适配器 | 配置只读路径、唯一稳定主体选择器/属性和 adapter 版本。验证无提交、登录、token 轮换等副作用；登录标记或 URL 不能代替稳定主体。 |
| 真实账号恢复验收 | 使用已有 KMS 保存 A，重建实例/Node 后核对 A；同账号刷新继续、切到 B/失效/撤销等待；核对原任务和已生效操作后再明确剩余步骤。 |
| 候选开关及安装渠道 | 后端、工作台、候选插件版本/渠道在 Goal4 对齐。正式全量检查、合并及发布仍由用户决定。 |

完成机制与受控验收不以这些输入全部可用为前提；真实账号/生产能力保持待验状态，不使用测试 provider 或匿名回落填补。

## 兼容与回滚注意

读取同时支持旧 state 和私有 v2 payload；新保存内容使用 v2。缺少证明的旧 profile 仍可供人工查看，自动任务等待重新取得可信证明；不静默为旧 profile 补上账号身份。

旧版本后端不认识 v2 payload。回滚应先关闭相应候选入口，保留密文并使用兼容 v2 的解码器；不可直接用旧解码器宣称恢复成功，不清库，不自动降级到匿名会话。没有新增数据库迁移；M1/M2 测试库所需 0067/0070/0071 与生产执行是分开的事项。

核验只证明配置站点在该检查点对应的状态与主体。核验期间状态变化会等待；不能承诺远端账号在动作执行的每个瞬间都不会被站点或其他设备改变。不得据此扩大任何提交、付款或生产权限。
