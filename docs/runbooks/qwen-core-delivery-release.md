## 数据库与回滚顺序

- `0059` 只有三个 ADD COLUMN，既有记录默认 `NULL/0/0`。应用进程加载新代码之前，必须确认 `tasks.execution_id`、`tasks.execution_revision`、`tasks.core_record_version` 存在并与迁移类型、NULL/default 一致；缺任一字段拒绝应用发布。
- 本地真实 MySQL 测试仅验证隔离合成库中的事务与字段行为，不证明生产迁移已经运行。生产迁移仍须独立备份、执行和只读校验。
- 失败恢复旧应用与旧静态版本，不通过 DROP COLUMN 回滚。保留新增字段及审计记录，禁止回放生成或重复扣额。核对本次合成任务已无活动句柄，避免旧版本续跑本次尚未结算的新格式记录；无法确认则停止灰度并保留现场。
- 两个 healthz、Orchestrator uid=998/单进程、revision、静态资源摘要及配置聚合前后核对。不能仅凭 HTTP 200 宣称功能成功。
