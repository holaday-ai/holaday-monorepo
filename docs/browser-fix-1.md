# Browser capability rollout and domain egress

All new infrastructure is off by default. This branch does not change deployment configuration.

- `BROWSER_V2_CANARY_USER_IDS`: comma-separated exact external user IDs. Enables viewport V2, observation V2, replay V1 and user-browser routing V2 for those authenticated users. Empty means no canary users. The existing four global flags continue to enable their respective capabilities globally. The backend returns effective capabilities via `browserReplay.capabilities`; the frontend no longer relies on `VITE_BROWSER_VIEWPORT_V2`.
- `BROWSER_DOMAIN_PROXY_ENABLED`: enables selective request proxying only when explicitly true.
- `BROWSER_DOMAIN_PROXY_DOMAINS`: comma-separated exact host suffixes, including subdomains. No wildcard matching outside a dot boundary.
- `BROWSER_DOMAIN_PROXY_URL`: operator-provided HTTP(S) upstream endpoint, optionally with authentication. Never put a real value in reports or source control. The task captures one endpoint configuration for its owned browser session. The optional `{session}` placeholder (including its percent-encoded form) is replaced with a stable opaque hash of the authenticated user/task and configured site domain. Configure that placeholder according to the provider's sticky-session syntax, or use an endpoint that already guarantees a fixed exit. A rotating provider without sticky-session support cannot guarantee an exit IP. No proxy is configured by this change.

The proxy validates each destination through the existing browser network policy and connects to its approved IP (including HTTPS CONNECT). Host/SNI preserve the original site. Only owned task pages and their popups are intercepted. HTTP payload request/response bytes are measured, not estimated wire-level provider billing. Video/audio, common stream endpoints, oversized uploads and responses are blocked. Failed connections and explicit proxy-unavailable responses fall back direct for GET/HEAD only; an ambiguous write is never retried. Counts and fallback/failure markers are retained as task evidence. Redirects are handled by Chromium and re-enter policy checking. Service-worker-originated requests cannot be intercepted by Playwright routing. New isolated contexts block service workers while the feature is enabled; proxy setup refuses an existing active worker, disables new registration in the cloud context, and stops the proxy if a worker appears.

Downloads are read with a 50 MiB cap and saved as a private task-temporary copy, then use the existing authenticated FileService output path. The Playwright-managed download may already have reached its browser temporary storage before this copy is read. Temporary files are removed on success or failure. The model receives only a stored file ID, filename, exact byte count, SHA-256 and download URL. Output attachment metadata includes the same receipt.

Regression: `pnpm --filter @holaday/orchestrator exec vitest run src/agent/browser-tools/browser-fix-acceptance.test.ts --maxWorkers=1 --minWorkers=1`. Public-site fixed-call check: `pnpm --filter @holaday/orchestrator exec tsx scripts/browser-fix-regression.ts /path/to/evidence`. No model keys or login required. Local receipts in that script are explicitly local evidence, not production file IDs.

The public-site script disables QUIC and HTTP/2 after the default Chromium transport timed out on Heroku while HTTP/1.1 succeeded. This is an explicit test transport setting, not a production rollout.
