# Goal3 M2：Chrome 任务截图交付

沿用已确认 Goal3 和单路执行；实际公开模型 Chrome 表单用例已证明缺少截图工具。原规范 §3.3 要求任务目标内截图，本计划修复该交付缺口。

设计：增加可选 `task_screenshot_v1`，保持六项必需 v2 能力兼容。独立只读命令绑定 session、插件观察 revision 和后端生成 captureId，不接受模型提供 tab、地址、路径或图片。驱动只对当前任务页面后台截图；遮罩所有可编辑控件以及敏感值的页面镜像，覆盖子 frame。遮罩失败不回退原始或可见标签截图。捕获前后核对文档、origin、执行权和人工输入；迟到或取消图片丢弃。

JPEG 有大小上限、SHA256 和绑定元数据。后端验证后，通过原任务 FileService 的普通 output 路径只保存一次；收到真实文件回执后才发布附件和完成截图要求。存储结果未知停止，禁止自动重试。模型只收到文件元数据。

- [x] 协议及驱动 RED→GREEN：可选协商、遮罩、文档改变、目标/权限丢失、上限、无前台操作。
- [x] session/transport/client：错误归属、旧 revision、取消/迟到、坏图片回执拒绝；不将只读失败分类为未知输入。
- [x] runner/FileService：真实保存回执和附件，失败/假完成防护，有限相关回归。
- [x] 原生真实双标签和像素遮罩验证；只重跑受影响公开模型 Chrome 表单。
- [x] 必要类型/静态/路由检查和Chrome完整App文件闭环通过；冻结、提交后接续主计划的云端文件缺口，Goal3不计完成。

验证限制：原生 QA profile 和合成站点证明候选行为；实际公开模型另记。真实用户安装、账号、KMS 和物理输入仍按已列输入分别验收。
