# DivineAPI 后台刷新设计

## 目标

在 DivineAPI Translator 持续需要约 21–25 秒响应的情况下，今日能量页面必须在 8 秒内提供可用内容，同时在真实中文运势准备好后无闪烁地升级页面内容。

## 已确认约束

- 前台等待上限保持 8 秒；不能让供应商延迟变成 20–30 秒加载动画。
- DivineAPI 后台请求硬上限为 35 秒，超时后必须终止。
- 前台等待超时后立即返回现有本地提示，不返回错误页。
- 后台请求不得因为前台返回而中止；成功后必须完成契约校验并写入现有缓存。
- 相同请求缓存键同时最多存在一个上游请求。
- 前端只静默复查当前仍可见且来源为 `local-fallback` 的星座周期。
- 真实内容到达时原位替换，不重新展示骨架屏或转圈状态。
- 用户切换资料、星座、周期或范围后，旧请求不得覆盖新状态。
- 不自动预热十二星座排行，不增加 12 倍上游请求和成本。
- 不更换 OpenAI key、不扩大 key 权限、不绕开 DivineAPI 自建翻译链路。

## 方案

### 服务端：前台预算与后台任务分离

`postDivineApiJson` 不再用同一个 8 秒计时器直接中止供应商请求。它先按无密钥参数构造缓存键，并查询现有新鲜或陈旧缓存。缓存未命中时，从进程级 in-flight map 获取或创建一个供应商任务。

供应商任务拥有独立的 35 秒 `AbortController`，负责请求、状态码检查、JSON 解析、DivineAPI 契约校验和缓存写入。任务结束后无论成功或失败都必须从 in-flight map 删除，避免永久占位。

调用方只等待以下两者先完成的一个：

1. 共享供应商任务返回；
2. 8 秒前台预算结束。

供应商任务在 8 秒内返回时，调用方继续获得 `fresh` DivineAPI 内容。前台预算先结束时，调用方返回一个可识别的“后台处理中”结果；业务读取函数据此使用本地提示，但供应商任务继续运行。若存在仍在 stale-if-error 窗口内的真实缓存，则优先返回 `stale`，不退回本地内容。

供应商任务真正失败时保留现有语义：有效陈旧缓存优先；无缓存则由上层返回本地提示。只有契约错误才临时标记 capability 失败；前台预算耗尽不能将 capability 标记为未授权或无效响应。

### 缓存与单飞键

缓存键继续包含实际 base URL、endpoint 和除 `api_key` 外的请求参数。in-flight map 使用相同键，确保：

- 同一星座、周期、范围、语言和日期共享一次请求；
- 中文 Translator 与英文主端点不会错误合并；
- 不把 API key 写入缓存键或日志；
- 后台请求成功后，下一次相同查询直接命中新鲜缓存。

测试辅助清理函数必须同时清除内容缓存、capability 失败状态和 in-flight map，保证测试隔离。

### 前端：静默复查和原位升级

`useEnergyAstrology` 在某周期完成加载且结果为 `local-fallback` 时，为该周期安排有限次数静默复查。第一次间隔覆盖供应商 21–25 秒响应窗口；推荐在初次请求结束约 20 秒后复查，使总时间落在 28–30 秒。若仍未命中，再做一次短间隔复查；总复查次数必须有上限。

静默复查复用现有 tRPC period query，但不把 `loading` 设回 `true`。页面继续展示本地提示和可操作内容。只有返回 `source: divineapi` 时才替换周期数据并清除“暂时使用本地提示”；再次返回本地内容或请求失败时保持当前状态。

静默复查仍使用每周期 request id、当前 range key 和当前 profile 身份守卫。组件卸载、资料变化、用户手动刷新或周期范围变化时，取消旧计时器并使旧响应失效。用户主动点击刷新仍保留可见加载反馈，不与静默复查混用。

### 数据流

1. 页面请求中文周期内容。
2. 服务端创建或复用 35 秒供应商任务，并等待最多 8 秒。
3. 8 秒内未完成：服务端返回本地提示；前端结束骨架屏并保持页面可用。
4. 供应商在后台完成、通过契约校验并写缓存。
5. 前端静默复查相同周期；服务端命中新鲜缓存。
6. 前端原位替换为 DivineAPI 中文内容，不出现第二次骨架屏。

## 错误处理

- 供应商超过 35 秒：中止任务、清理 in-flight map，保留本地或陈旧内容。
- HTTP、JSON 或契约失败：不缓存坏响应；契约失败沿用 capability 临时降级。
- 后台 promise 必须有完整 catch/finally，不能产生未处理拒绝。
- 静默复查失败不清空页面，也不显示新错误；用户仍可手动刷新。
- 进程重启会丢失内存缓存和 in-flight 状态，这是可接受的；不新增数据库持久化。

## 测试

### 服务端

- 供应商在 8 秒内完成时返回新鲜内容并缓存。
- 8 秒前台预算结束时返回后台处理中，供应商 signal 尚未 aborted。
- 供应商随后完成时写入缓存；第二次查询直接获得新鲜内容。
- 两个相同并发请求只调用一次 fetch。
- 35 秒硬上限会 abort fetch 并清理 in-flight；后续请求可重试。
- 存在有效陈旧缓存时，前台预算或供应商失败返回 stale。
- 前台预算耗尽不会标记 capability 失败。

### 前端

- 初次本地回退结束可见加载态并安排静默复查。
- 静默复查期间 `loading` 保持 false，不重新出现骨架屏。
- 静默复查获得 provider 内容后原位升级并清除本地提示。
- 静默复查再次回退或失败时保持当前本地内容。
- profile、range 或手动请求变化后，旧静默结果不能覆盖新状态。
- provider 首次成功时不安排静默复查。
- 排行查询行为不变且不会自动预热。

## 上线验证

- 保持现有 8 秒页面可用标准。
- 使用生产 Translator 实测：首次显示本地提示后，约 25–35 秒内自动升级为 DivineAPI 中文内容。
- 升级过程中页面无第二次骨架、无控制台错误、刷新按钮保持可用。
- 同一周期服务端观察到单次上游调用；缓存命中后再次刷新明显快于供应商响应。
- Aliyun 与 Vultr bundle 一致、healthz 200、PM2 online/restart 0、P0 smoke 通过。

## 非目标

- 不实现通用任务队列或持久化 provider job。
- 不将所有星座内容一次性预取。
- 不改变 DivineAPI 套餐、Translator 模型或 OpenAI key 权限。
- 不重构今日能量视觉布局和其他互动模块。
