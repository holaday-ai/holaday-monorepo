# 安全接纳、排空与发布维护设计

状态：用户于 2026-09-10 同意完整生命周期关闸、等待后台结束和安全升级/回滚方向。本文落实该方向；不代表实现完成或生产可发布。

## 目标与不变量

发布或关闭灰度前，先原子地停止新的相关任务，再等待已接收的请求、待派发回调、原始数据库操作、模型调用和保存全部结束。任务的主结果仍可先交付，后续建议不延迟用户收到结果，但在内部继续计入生命周期。

“API 已返回”“数据库 completed”“registry 空”“安静日志”“进程重启后内存为零”均不作为排空证明。原始操作未结束与提交结果未知分开计数；未确认结果不重发、不改任务状态清场。控制器无法证明安全时保持关闭，报告阻断。

约束：任务内存预算约 10GB；Node 堆 2GB；Vitest 单 worker、每批最多 20 文件；重任务串行。不安装、不新启 Docker/浏览器。保护主工作区草稿与 PR237 冻结包。支付、奖励、提现、Partner Ledger、额度规则、账号注销、DivineAPI 和旧供应商配置不变。不输出密钥、身份或业务文本。

## 一、生命周期所有权

新增进程内 `ExecutionDrain`，默认关闭接纳；由受控启动流程开放，不能在模块导入时自动开放。根操作在路由首个 await 前登记，完整覆盖幂等 claim、附件读取、原有额度调用和创建/回复，不改变其业务规则。无法识别是否属于受保护分支时先登记，不能先执行副作用再登记。

使用不透明对象句柄，以对象身份验证归属；不得接受任务 ID、复制句柄或其他实例的句柄。已接收操作可以在关闭接纳之后派生子操作，但必须在派发之前同步登记，且不能从已释放的句柄继续派发。父操作结束不释放子操作。容量固定有界，耗尽拒绝新工作而不是漏记。计数只公开固定类型的聚合状态，不暴露业务标识。

原始 Promise 的 owner 仅用于派生和核验，普通 finish 不能释放它。包装器同步取得唯一私有释放能力，只有原始 Promise 的 finally 持有该能力。调用方即使超时、提前调用 finish 或尝试重复 pin，物理在途计数也不能消失。

每个原始 DB/transport Promise 在派发前取得子句柄；外层超时只结束用户等待，不结束子句柄。错误若不能证明远端未提交，登记独立不透明 uncertainty ticket；物理调用结束仍保留未知标记。对账层在核对原有事务/执行版本证据后才持票解除；计数器本身不判断业务对账证据，也不提供按 ID 清空或全局 reset。进程重启不能生成新的“已对账”事实。

`snapshot()` 返回关闭/接纳状态、活动总数、根数、子数、未知数和固定工作类型计数。只有关闭接纳、活动为零、未知为零且未被永久阻断，才可报告本实例 idle。此报告单独不能证明整个进程、其他 boot 或生产安全。

## 二、持久关闸和本机控制

本机控制采用权限受限 Unix socket，不新增公网接口或密钥。父目录与 socket 所有者、权限、真实路径、软链接和大小均严格检查。固定协议仅允许状态、关闸、条件开放；每条命令绑定发布 epoch、候选 revision、boot 身份及单调版本，不接收自由文本或 shell 参数。异步控制命令串行，不允许竞争开放。

在启动任何入口/调度器前读取持久关闸与旧 boot 状态；缺失、损坏、权限异常或未收口的旧 boot 一律保持关闭。关闸确认必须晚于持久化成功；本轮租约过期、控制器失联、应用异常均不得自动开放。生命周期首次变为非空前同步记录 dirty，完全归零并且无未知后才允许写 clean；写失败永久阻断本实例。完整协议由独立的文件状态模块负责，不把 JSON 文件存在当作业务完成证明。

控制面不得提供任意“确认完成”入口。开放必须同时满足匹配 epoch/boot/候选、有效时间窗、当前真实计数、旧 boot 对账、未消费的开放授权及现有单账号灰度规则。正常静态资源和只读健康响应不能决定开放。

## 三、真实入口与完整链覆盖

同一 Orchestrator 重启会影响多个入口。逐项登记任务 create/reply、后台调度入口、核心生成、建议、计划、verifier、scrape 与实际 messages/responses adapter 调用。缓存 adapter 在实际派发时也必须持有效所有权。不能只改 resolveCore。未覆盖的执行入口须显式阻断发布资格，不将局部 drain 标成整个进程 idle。

后续建议在主 handle 释放前预留生命周期子句柄；其前置 DB、模型请求、保存与发布均在子操作内。主任务交付契约不改。底层 RecoveryBudget 和 shell INSERT 超时不释放原始 Promise 的生命周期。运行中的其他系统不会因加入计数而被取消。

等待用户的任务不是活动操作本身。发布工具只可接受本次单一合成任务与准确执行版本、持久化 settlement 相符且所属请求/子工作均收口的 parked 记录；其他 awaiting_user 仍按原保守规则拒绝。

## 四、首次维护与回滚

PR231 没有此机制，因此首次安装和降级回滚是独立门禁。执行器必须持有外部停止相关接纳、内部调度已处置、旧在途工作已收口的可信证据，且覆盖整个被重启进程。任何一项无法证明，返回 `BOOTSTRAP_UNPROVEN`，不重启、不切换、不伪造 drain 回执。

外部维护闸门必须保持到新版本明确完成初始化/对账，或旧版本恢复并完成旧工作核对；PR231 不理解新状态文件，不能在回滚后依赖它自动保护。失败时不扩大白名单、不删除业务任务、不DROP新增列、不重放生成或扣额。若现有旧进程无法提供所需证据，保留关闭状态并报告真实未知，不承诺可无人值守完成首次切换。

本设计批准建设维护机制，不批准假设旧任务已完成。上线前还必须完成实际入口/调度覆盖表、维护协议实测及有效新发布窗口。旧 08:30 夜间窗口已过，不复用。
