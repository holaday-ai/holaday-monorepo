# HOLA DAY 股市任务：可信的 AI 自选股研究工作台设计规格

## 1. 背景与问题

HOLA DAY 股市任务当前同时承载行情、新闻、公告、自选股、AI 问答和定时简报，但产品结构更接近一个缩小版资讯门户，尚未形成清晰的用户任务闭环。2026-08-16 的生产环境审计暴露出直接影响信任的 P0 问题：页面在 08-16 仍以 08-11 的行情和资讯呈现“今日”“最新”“机会”等当前时态，用户无法判断数据过期是休市、数据源故障、缓存回退还是刷新失败。

这不是单个日期标签的视觉问题，而是数据日期、缓存策略、内容排序、AI 任务上下文和页面语义没有被同一份可信状态约束。只修正文案或强制刷新都不能解决根因。

## 2. 产品定位

股市任务定位为 **可信的 AI 自选股研究工作台**，而不是实时交易终端、行情大全或通用财经新闻门户。

核心承诺：

> 自动监控我的关注股票，告诉我发生了什么、为什么值得关注、证据是什么，以及下一步需要持续追踪什么。

核心用户是需要在工作间隙快速维护关注清单、理解变化和委托后续研究的非专业或半专业投资者。页面首先回答“我的股票有什么值得看”，其次才补充市场背景。

专业产品参考原则：

- TradingView 与 Koyfin 将自选股、新闻、指标和告警聚合到持续监控工作流，而不是让用户反复浏览孤立模块。
- Seeking Alpha 将组合健康、风险提示和关注事项置于单纯资讯流之上。
- HOLA DAY 的差异化不在更全的行情，而在 AI 能基于一份明确的数据快照继续研究、生成简报并持续监控。

## 3. 目标与非目标

### 3.1 目标

1. 任何行情、新闻、公告、AI 结论都能说明数据日期、来源和当前可用性。
2. 上游异常时自动进入降级或历史回看模式，旧数据不得继续使用当前时态。
3. 首屏以用户自选股的重要变化和待处理事项为核心，而不是通用新闻轮播。
4. AI 快捷任务绑定确定的数据快照与证据集合，页面和任务结果不再各说各话。
5. 将自选股、证据阅读、AI 研究、定时简报和持续监控组成可循环的工作流。
6. 390px 移动端可完成查看重点、打开证据、发起研究和管理关注，不发生遮挡或裁切。
7. 基于可验证事实主动警示风险，并允许用户把风险信号转成持续提醒。
8. 将用户明确表达的选股需求转成透明、可修改的条件，在股票池中找出符合条件的候选股票。
9. 基于用户主动提供的信息、自选股和筛选历史，总结其选股偏好的优势、局限和集中风险。

### 3.2 非目标

- 不提供交易下单、券商账户连接、持仓盈亏或自动交易。
- 不承诺逐笔或交易所级实时行情；所有延迟必须如实标注。
- 不生成买入、卖出、目标价或收益承诺，不将研究信息包装为投资建议。
- 不生成“推荐指数”“最值得买”或无法解释的 AI 综合分；匹配度只表示用户明确条件的满足程度。
- 不把浏览、点击等弱行为直接解释为风险承受能力，也不在未完成合规评估时收集不必要的资产、收入或债务信息。
- 不以增加更多通用资讯卡片作为内容丰富度目标。
- 本轮不扩展美股、港股的深度研究能力；跨市场资讯可以保留，但不能压过 A 股自选股任务。
- P0 不重写现有 A 股分析引擎和合规闸门，只修复其数据入口、上下文绑定和可信边界。

### 3.3 个性化选股的合规边界

在未完成适用地区的证券投资咨询资质评估或持牌机构合作前，HOLA DAY 只提供 **用户条件驱动的可解释筛选**：用户先明确行业、市值、估值、盈利、现金流、波动、流动性、事件和排除条件，系统负责转换、执行和解释这些条件。候选结果不得表述为适合购买、建议持有或预期上涨。

自然语言可以帮助用户构造条件，但不能静默加入用户未表达的投资判断。系统必须展示解析后的条件，允许逐项修改，并同时展示满足项、不满足项、缺失数据、风险警示、数据日期和证据。用户可以把候选加入自选、对比、深挖或监控，但不存在交易动作。

原因是现行《证券投资顾问业务暂行规定》将投资品种选择等个性化投资建议纳入证券投资顾问业务；《证券期货投资者适当性管理办法》同时强调投资者分类、风险承受能力、投资目标、风险揭示和动态管理。产品文案中的“非投资建议”声明不能替代实际业务边界、留痕和适当性义务。

## 4. 已确认的生产审计结论

### 4.1 数据与信任

- 股市首页首次可用约需 17 秒。
- 08-16 页面显示 `数据日期 08/11`，发现流首屏也主要是 08-11 内容；最新有效交易日与页面数据不一致。
- 页面虽有稳定日期元数据，但内容区仍使用“今日”“最新”“机会”“强势”等当前语义，形成自相矛盾的信任体验。
- 当前缓存和回退可以让旧快照长期存活，服务不可用与合法休市没有形成面向用户的不同状态。

### 4.2 信息架构

- “发现”通用新闻先于用户自选股核心任务，且大卡轮播占据大量首屏空间。
- “亮点”和“明星股票”重复表达关注对象，信息密度低。
- 每日简报说明自己只提供 08-11 历史内容，却继续使用“机会 / 风险 / 需要追踪 / 最新动态”等当前标签。
- 新闻详情的来源边界基本可信，但标题重复，缺少“为什么与我相关”和事件时间线。

### 4.3 排序与任务闭环

- 发现流排序偏重关联股票、摘要长度和封面图，没有把发布时间作为第一层约束，导致旧内容排在更新内容之前。
- AI 快捷指令只提交自然语言与 `taskSource: stock_dashboard`，没有绑定 `symbol`、`snapshotId`、`dataAsOf` 和证据来源。
- 自选股编辑只有基础增删，缺少分组、排序、告警条件、上次运行和下次运行状态。

### 4.4 移动端与可访问性

- 390px 宽度下存在标题被菜单挤压、通知层遮挡、输入提示被截断和通用资讯挤占任务区域的问题。
- 现有自动测试把行情自动刷新设计为“视觉静默”，却没有验证过期数据会切换整页语义，说明测试策略本身需要修正。

## 5. 信任状态模型

### 5.1 单一可信快照

所有首页模块和从首页发起的 AI 任务必须共享一个不可变的快照信封：

```ts
type TrustMode = 'current' | 'delayed' | 'historical' | 'unavailable';
type SourceStatus = 'healthy' | 'delayed' | 'failed' | 'disabled';

interface StockSnapshotEnvelope {
  snapshotId: string;
  generatedAt: string;
  marketTimezone: 'Asia/Shanghai';
  marketSession: 'preopen' | 'open' | 'lunch' | 'closed' | 'non-trading';
  latestExpectedTradingDate: string;
  dataAsOf: string | null;
  trustMode: TrustMode;
  sources: Array<{
    key: 'quotes' | 'indices' | 'news' | 'announcements';
    status: SourceStatus;
    dataAsOf: string | null;
    fetchedAt: string | null;
    errorCode?: string;
  }>;
}
```

页面不得从不同请求临时拼出互相冲突的日期。行情、指数、关注变化、每日概览和任务快捷入口使用同一个 `snapshotId`；新闻和公告可以有独立发布时间，但必须挂在同一信封的来源健康状态下。

### 5.2 最新有效交易日

后端使用 A 股交易日历和 `Asia/Shanghai` 计算 `latestExpectedTradingDate`：

- 非交易日取最近一个有效交易日。
- 交易日 09:45 前，日线收盘数据允许以上一个交易日为最新有效日期。
- 交易日 09:45 后，行情能力必须能确认当日数据；不能确认时进入 `delayed`，不得继续显示为 `current`。
- 交易日 16:00 后，日线快照必须落到当日，否则进入 `historical`。

节假日、周末和上游故障因此具有不同解释，不再简单比较设备自然日。

### 5.3 模式判定与文案规则

| 模式 | 判定 | 页面行为 |
| --- | --- | --- |
| `current` | 必要数据源健康，行情日期符合最新有效交易日 | 可使用“今日”“最新”；仍显示数据日期 |
| `delayed` | 当日服务可用但抓取时间或关键源超过服务窗口 | 显示“数据延迟”；允许浏览，不声称实时 |
| `historical` | 行情日期早于最新有效交易日，或回退到旧快照 | 整页切换“历史回看”；替换所有当前时态；禁用依赖当前数据的任务 |
| `unavailable` | 没有满足最大陈旧期的可信快照，或关键源不可验证 | 不渲染旧数值；显示明确错误、最后成功时间和重试入口 |

受模式约束的词包括但不限于：今日、最新、当前、机会、强势、异动、现价、实时。历史模式统一改为“截至 {dataAsOf}”“当日表现”“当时的关注点”“历史记录”。该转换由语义组件或结构化字段完成，不依赖散落的字符串判断。

## 6. 页面信息架构

页面从上到下固定为以下十层。

### 6.1 市场与数据可信栏

首屏最上方常驻，展示：

- 当前市场状态与时区；
- 最新有效交易日和本页数据日期；
- 行情、新闻、公告来源健康；
- 刷新状态、最后成功时间和“查看数据说明”。

`historical` 和 `unavailable` 使用横跨内容区的低噪声但不可忽略状态条。状态不可仅靠颜色表达，并由屏幕阅读器播报一次，后台轮询不得反复播报。

### 6.2 今日待关注

首页第一内容区，只展示 3–5 条与自选股直接相关且可解释的重要变化。每条包含：

- 股票名称与代码；
- 发生了什么；
- 为什么值得关注；
- 数据日期、事件发布时间和来源；
- `查看证据`、`让 AI 深挖`、`持续监控` 三类动作。

没有足够证据时宁可少展示，不用通用资讯补满。历史模式标题改为“{dataAsOf} 回看重点”。

### 6.3 自选股工作台

用紧凑、可排序的表格或列表替代巨型“亮点”卡片。桌面端默认列为：股票、价格与涨跌、变化摘要、最新事件、风险提示、数据时间、监控状态。移动端折叠为单列卡片，仅保留股票、变化摘要、日期和主动作。

点击股票打开同页抽屉，包含行情摘要、新闻、公告、风险变化、已有监控和 AI 快捷动作。首版支持：

- 拖拽或键盘调整排序；
- 自定义分组；
- 按变化、事件时间、风险或自定义顺序排序；
- 查看该股票的最近简报与监控状态。

“亮点”和“明星股票”不再作为两个独立模块，原有能力合并到工作台的默认排序和变化摘要中。

### 6.4 风险雷达

风险雷达不是推荐的反面，而是事实驱动的预警层。它覆盖业绩恶化、减持与质押、诉讼和监管处罚、退市风险、估值异常、波动异常、成交萎缩、行业集中及数据异常。每条警示必须包含：

- 严重程度：`关注`、`警示`、`高风险`；
- 已确认事实、触发阈值和为什么与用户相关；
- 事件时间、数据日期、来源和证据链接；
- `查看证据`、`让 AI 解释`、`持续提醒`；
- 解除条件或下一次复核时间。

事实、规则判断和 AI 解释分层展示。缺少必要字段时标记“无法判断”，不得把缺失数据当作安全。风险严重程度不能由生成模型自由决定，而由可审计规则和经过版本管理的阈值产生。

### 6.5 我的条件选股

用户可以用自然语言或结构化控件描述需求，例如：“最近三年持续盈利、资产负债率低于 50%、市盈率不过高、排除 ST 和近期减持”。系统先展示解析后的条件，再在明确股票池和同一可信快照上执行筛选。

```ts
interface StockScreenCriterion {
  id: string;
  field: string;
  operator: 'eq' | 'neq' | 'gt' | 'gte' | 'lt' | 'lte' | 'between' | 'in' | 'not_in';
  value: string | number | Array<string | number>;
  unit?: string;
  sourceField: string;
}

interface StockCandidateMatch {
  symbol: string;
  snapshotId: string;
  dataAsOf: string;
  matchedCriteria: string[];
  unmetCriteria: string[];
  missingCriteria: string[];
  warningIds: string[];
  evidenceIds: string[];
}
```

结果默认按“满足的硬条件数量 → 缺失数据最少 → 用户选择的排序字段”排序，不产生不可解释的 AI 总分。每张候选卡清楚回答“为什么入选、哪里不符合、还缺什么数据、有什么风险”。如果没有完全匹配项，系统展示零结果并允许用户主动放宽某一条件，不私自修改需求。

### 6.6 选股偏好画像

偏好画像只使用用户主动设置的条件、自选股结构和明确的筛选/收藏行为，并显示推断依据与置信度。画像维度包括行业、市值、估值、盈利质量、成长、现金流、波动、流动性、事件偏好和持有周期。输出分为：

- `偏好事实`：可验证的分布和变化；
- `可能优势`：这种风格在什么环境下更稳健或更容易理解；
- `潜在盲点`：行业集中、单一因子、追逐热点、忽视流动性或成长性等；
- `补充视角`：供用户研究的反向条件，不直接新增候选或改变筛选；
- `依据与控制`：数据来源、统计窗口、置信度，以及修改、关闭、清空入口。

画像不评价用户“聪明”或“保守”，不把历史偏好等同于适当性结论，也不使用偏好画像替用户自动买卖或静默扩大风险。

### 6.7 证据流

发现页和首页证据流使用同一排序规则，排序优先级为：

1. 新鲜度窗口；
2. 公告或事件的重要性；
3. 与自选股、当前打开股票的相关性；
4. 来源可信度；
5. 摘要完整度和视觉素材。

封面图只能作为展示质量因素，不能让旧内容越过更新的相关内容。超过主新鲜度窗口但仍有研究价值的内容进入“背景资料”，明确显示原始发布时间，永不标记为“最新”。

新闻详情去除重复标题，新增“为什么与我相关”、相关股票和事件时间线。所有分析句与来源摘要视觉分离；无正文时继续明确提示只有来源摘要并提供原文链接。

### 6.8 AI 研究与持续监控

快捷动作不再是全局静态问题，而是围绕当前股票、事件或快照生成。发起任务时必须携带：

```ts
interface StockTaskContext {
  taskSource: 'stock_dashboard';
  symbol?: string;
  snapshotId: string;
  dataAsOf: string;
  evidenceIds: string[];
  trustMode: 'current' | 'delayed' | 'historical';
}
```

任务执行开始时校验快照仍存在且来源可追溯。结果页固定显示“分析基于 {dataAsOf} 数据”、快照编号和证据链接。若用户选择刷新到新快照，创建新任务或明确记录上下文升级，不静默替换原任务证据。

`historical` 模式只开放“回看 / 复盘 / 基于历史证据解释”类动作，禁用“分析今天走势”“生成今日关注日报”等依赖当前数据的入口。`unavailable` 模式不允许提交数据型分析任务。

### 6.9 市场背景

指数、行业和通用市场新闻放在个性化内容之后，作为解释自选股变化的背景。保留 A 股、港股、美股分类，但默认不让跨市场通用新闻占据首屏。每个面板独立显示 `dataAsOf` 或发布时间范围。

### 6.10 简报与告警中心

将现有每日简报从静态内容块提升为可管理的持续任务：

- 显示下一次运行、上次成功、上次失败与失败原因；
- 默认 08:30 和 15:30（`Asia/Shanghai`）的既有计划继续保留；
- 支持针对自选股分组选择简报范围；
- 支持价格变化、公告、新闻、风险信号等监控条件；
- 每条简报和告警都能回到触发证据和对应快照。

## 7. 系统架构与数据流

### 7.1 服务边界

- `apps/akshare-mcp` 负责上游请求、协议归一化和短期原始缓存。
- `apps/orchestrator` 负责交易日判定、来源健康、快照生成、最大陈旧期、证据归一化、发现排序和任务上下文校验。
- `apps/web-workbench` 只消费结构化信任状态，不自行猜测最新交易日或通过设备日期修正文案。
- 现有 A 股分析引擎继续负责事实卡、风险雷达、趋势解释、QA 与合规闸门，但只能读取任务绑定快照。

### 7.2 请求流程

1. 首页请求轻量 `stock trust summary`，优先返回最近一次已验证信封。
2. Orchestrator 根据交易日历判断是否需要刷新，单飞触发数据抓取，避免每个浏览器并发击穿 AkShare。
3. 每个上游调用有硬超时、并发上限和熔断器；成功数据先校验日期、结构和来源，再生成不可变快照。
4. 页面先渲染信任栏和骨架，再按“待关注 → 自选股 → 证据流 → 市场背景”渐进加载。
5. 用户发起 AI 任务时，前端提交快照上下文；后端重新校验快照归属、日期和证据 ID 后入队。
6. 简报和告警任务记录运行所用快照，运行历史可回溯到证据。

### 7.3 超时、缓存与熔断

- AkShare 单次上游调用必须有硬截止时间；客户端取消后服务端也要停止或隔离失控工作，不能让挂起请求占满工作线程。
- 同一数据集刷新使用 single-flight；失败后使用指数退避和带抖动重试，不由页面轮询制造重试风暴。
- 熔断器按数据源记录连续失败和半开探测；断路时快速返回明确状态，不等待完整超时。
- 可以 stale-while-revalidate，但旧快照一旦早于 `latestExpectedTradingDate` 就只能以 `historical` 返回。
- 超过配置的最大陈旧期后进入 `unavailable`，不再无限期展示旧数值。最大陈旧期按数据域配置并记录在监控中，不由前端覆盖。
- 快照写入必须是原子的；部分源成功不能覆盖上一份完整快照，只能形成带来源状态的新信封。

## 8. 错误与空状态

| 场景 | 用户状态 | 可用动作 |
| --- | --- | --- |
| 合法休市且数据为最近交易日 | `current` + “休市” | 正常回看、研究、设置监控 |
| 当日行情延迟 | `delayed` | 查看已有证据、重试；不声称实时 |
| 只能取得旧快照 | `historical` | 历史复盘、查看证据；禁用当前数据任务 |
| 行情失败但新闻正常 | 整体不高于 `historical`，来源栏分别说明 | 阅读新闻、历史研究；不显示伪现价 |
| 没有可信快照 | `unavailable` | 重试、查看最后成功时间和服务说明 |
| 自选股为空 | 引导添加 3–5 只股票并说明收益 | 添加股票或查看市场背景 |
| 证据为空 | 明确“当前没有符合条件的新事件” | 调整范围；不使用合成新闻占位 |
| 任务快照失效或越权 | 阻止入队并解释原因 | 刷新页面后基于新快照重试 |

错误信息不得直接暴露上游堆栈、请求参数或凭据。内部保留结构化 `errorCode`、source、duration、attempt 和 circuit state，便于观察和告警。

## 9. 交互、视觉与可访问性

- 保留 HOLA DAY 现有安静、专业的浅色工作台语言，信任状态优先依靠文字、图标和布局，不使用大面积警告色制造恐慌。
- 首屏减少轮播和大图；金融研究内容以紧凑表格、分组列表、抽屉和证据卡为主。
- 仅在真正有新结果时使用动效；后台刷新不导致列表跳动、焦点丢失或滚动位置变化。
- 所有图标按钮同时具备可访问名称和原生 `title`；完整键盘路径覆盖可信栏、自选股排序、抽屉、证据详情和任务动作。
- 状态更新使用适当的 live region；轮询过程不重复播报相同状态。
- 390px 视口下页面标题、菜单、通知、搜索/提问输入和主操作互不遮挡；触控目标不少于现有产品标准。
- 支持 `prefers-reduced-motion`，表格到卡片的响应式切换不丢失数据日期和来源。

## 11. 测试与验收

### 11.1 自动测试

- 交易日历：工作日、周末、法定节假日、节前节后、09:45 和 16:00 边界。
- 信任状态：当前、延迟、历史、不可用，以及各来源部分失败。
- 缓存与恢复：single-flight、硬超时、熔断开闭、最大陈旧期、原子快照和重启恢复。
- 文案策略：历史模式不得出现受限的当前时态；现有“视觉静默刷新”测试改为信任模式优先。
- 排序：新鲜内容优先；旧但重要内容只能进入背景资料；封面质量不能提升时间层级。
- 任务契约：快照归属、日期、证据 ID、防篡改、快照失效、结果溯源和合规输出。
- 风险雷达：规则阈值、严重程度、缺失数据、解除条件、证据溯源和告警去重。
- 条件选股：自然语言解析预览、条件修改、零结果、完全/部分匹配、缺失字段、稳定排序和禁止隐式放宽。
- 偏好画像：最小样本、统计窗口、置信度、优势与盲点依据、用户修改/关闭/清空和弱行为不进入适当性判断。
- 前端：每个状态的加载、空、错误、部分失败、抽屉、排序、简报运行状态。
- 可访问性：键盘路径、焦点恢复、名称与 `title`、live region 和 reduced motion。

### 11.2 上线硬门槛

1. 生产行情 `dataAsOf` 与最新有效交易日一致；若不一致，所有受影响模块必须进入明确的历史或不可用状态。
2. 历史模式中不存在“今日 / 最新 / 当前机会 / 强势”等误导语义，依赖当前数据的任务不可提交。
3. AkShare 服务挂起、失败或返回旧日期时，旧快照不能无限存活，页面请求不能持续等待。
4. AI 任务结果与发起页使用同一 `snapshotId`、`dataAsOf` 和证据集合，且证据链接可打开。
5. 发现流中，新鲜度先于封面和摘要长度；背景资料有明确日期和分区。
6. 390px 移动端无裁切、遮挡和核心动作不可达。
7. 关键用户路径在键盘和读屏下可完成，且状态不只靠颜色表达。
8. 生产 smoke 必须覆盖真实数据日期、来源健康、任务入队、结果溯源和降级演练，不能只验证 HTTP 200 或组件渲染。
9. 条件选股逐项解释匹配、不匹配和缺失数据；不得出现“推荐指数”“最值得买”或系统私自放宽条件。
10. 每条风险警示都能回到触发规则与证据；生成模型不能自行决定严重程度。
11. 偏好画像显示依据、统计窗口和置信度，并能由用户修改、关闭和清空。

### 11.3 产品验收路径

1. 用户进入页面，5 秒内看懂市场状态、数据日期和自己的首要关注事项；数据区可以继续渐进加载。
2. 用户从一条待关注变化打开证据，能区分来源事实与 HOLA DAY 解释。
3. 用户一键让 AI 深挖，结果明确说明基于哪一天、哪份快照和哪些来源。
4. 用户把结论转成监控或简报，能看到下一次运行和之后的运行记录。
5. 模拟上游旧数据和超时，页面自动切换历史或不可用状态，且不出现任何伪“今日”表达。
6. 用户输入自然语言选股要求，检查解析条件后看到逐项可解释的候选结果，并能把候选加入自选或监控。
7. 用户打开偏好画像，能理解自己的集中偏好、优势和盲点，并能纠正或删除画像。

## 12. 发布、观测与回滚

- P0、P1、P2 属于同一产品方向，但按风险拆分提交和 PR；P0 先独立上线验证，不能与大规模页面重排一起首次暴露。
- 新信任信封、任务上下文和新首页通过独立特性开关发布；先内部账号，再小流量，最后全量。
- 发布看板至少包含：首屏可信摘要延迟、快照年龄、预期交易日不匹配率、来源失败率、熔断状态、历史/不可用模式占比、任务上下文拒绝率和证据链接成功率。
- 回滚 UI 时仍保留后端数据可信保护；不得回滚到“旧快照继续作为今日数据”的行为。
- 若新快照生成异常，关闭生成开关并进入明确的历史/不可用模式；禁止用移除状态条或延长缓存冒充恢复。
