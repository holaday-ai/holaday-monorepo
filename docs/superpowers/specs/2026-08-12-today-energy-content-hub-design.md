# 今日能量内容补给站扩展设计

日期：2026-08-12
状态：已确认，待实施计划

## 1. 目标

将“今日能量”从约两分钟即可浏览完的轻量页面，扩展为用户等待 Holaday 自动执行任务时愿意停留、可以持续探索的内容补给站。

本轮不把页面做成无目的的无限信息流，也不提前建设完整广告系统。首期目标是：

- 不接入视频的情况下，提供约 10–20 分钟的有效内容；
- 抽卡和轻测试没有“一次结束”的死路，完成后始终有清楚的下一步；
- 充分使用当前已授权的星座日、周、月、年运势与六维数据；
- 对真实 API、本地内容和不可用能力做准确标识；
- 为未来的视频、小游戏、赞助内容和奖励体系预留稳定扩展位。

## 2. 已确认的用户与商业场景

主要使用者是正在等待 Holaday 自动执行任务的 staff。此时他们需要短暂解压、放松和获得情绪价值，同时仍能看见任务状态，并在任务完成后快速返回结果。

未来内容板块会增加：

- 更完整的小游戏；
- 视频观看；
- 广告和赞助内容；
- 基于观看或游玩行为的奖励。

因此，本轮采用“混合内容补给站”架构：真实星座 API、Holaday 自有内容、轻测试、抽卡和未来媒体内容使用统一内容目录，但本轮不接入广告平台、不建立现金或任务额度兑换机制。

## 3. 生产 API 核验结论

2026-08-11 至 2026-08-12 使用生产环境现有 DivineAPI 凭据进行只读探测，未输出或保存凭据。探测结论如下：

| 能力 | 实测结果 | 本轮处理 |
|---|---|---|
| 每日星座 | 英文端点已授权 | 接入六维与幸运信息；中文域未就绪时使用明确标注的本地中文内容 |
| 每周星座 | 已授权 | 修正请求参数后接入六维与百分比 |
| 每月星座 | 已授权 | 新增月运展示 |
| 每年星座 | 已授权 | 新增年运展示 |
| DivineAPI 中文翻译 | 未选择 Translator | 新增独立配置；未启用前不得向英文域发送 `zh` 并标记为成功 |
| 中国生肖 | 未授权 | 本轮不展示真实中国生肖内容 |
| 数字命理 | 未授权 | 仅保留明确标注的 Holaday 本地今日数字测试 |
| 每日塔罗 | 未授权 | 使用 Holaday 能量牌库，不标记为 DivineAPI |
| 是／否塔罗 | 未授权 | 使用 Holaday 能量牌库，不标记为 DivineAPI |
| 爱情、天使、梦想、职业等牌阵 | 未授权 | UI 通过能力表控制；开通套餐后启用真实接口 |
| 过去／现在／未来三张牌 | 未授权 | 先提供 Holaday“回顾／当下／下一步”三张能量牌，开通后切换真实牌阵 |

官方 Horoscope Starter 包含日、周、月、年运势、六个生活维度与幸运信息：

- <https://divineapi.com/horoscope/horoscope-api>

官方 Tarot Essentials 包含 7 种牌阵与“过去／现在／未来”；Tarot Gold 包含全部 20 种一、二、三张牌模式：

- <https://divineapi.com/tarot/tarot-api>
- <https://developers.divineapi.com/horoscope-and-tarot-api/past-present-future-reading>

### 3.1 已发现的现有实现问题

1. DivineAPI 业务拒绝使用 HTTP 200 和 `success: 2` 返回；现有代码只判断 HTTP 状态，因此会把无权限响应当成真实提供方成功。
2. 周运请求发送 `h_week=current`，官方参数为 `week=current`。
3. 中文请求发送到英文域，官方明确要求使用 Translator 域名；生产账户当前没有选择 Translator。
4. 前端把日运、周运和塔罗合并为一个 `source`，其中任意请求看似成功就会把整组内容标为真实提供方。
5. 当前服务只提取少数字段，丢弃六维百分比、幸运数字、幸运字母、宇宙提示、单身和伴侣建议等内容。

这些问题必须作为 P0 先修复，否则后续扩充会放大错误来源标识。

## 4. 产品原则

### 4.1 丰富但不繁琐

首屏继续维持当前明亮、轻松和低压的主视觉。深度内容从星座能量卡下方逐步展开，通过页签、横向内容轨道和折叠模块控制长度，不把全部文字同时堆在页面上。

### 4.2 内容可持续而非假随机

- 每日星座和每日牌在同一天保持稳定；
- 可重玩的抽卡模式、测试和底部内容组允许继续探索；
- 同一会话内尽量避免重复；
- 不把同一条缓存内容换标题后伪装成新内容。

### 4.3 来源真实

每个内容模块单独记录来源：`divineapi`、`holaday-editorial` 或 `local-fallback`。来源状态不能在页面层被合并成一个笼统的“真实 API”。

### 4.4 等待期间可随时退出

页面持续显示低干扰的任务运行状态。任务完成时给出明确提醒和“查看任务结果”入口；任何体验都可以暂停或退出，不制造强制停留。

## 5. 页面信息架构

页面顺序如下：

1. 当前 Hero 与能量选择；
2. 抽卡、小游戏、轻测试三项主入口；
3. 成长与完成记录；
4. 你的星座能量摘要；
5. 星座能量世界；
6. 抽卡实验室；
7. 轻测试馆；
8. 等待休息区；
9. 页面内任务状态条。

首页摘要只负责推荐和进入体验，完整内容区负责延长探索。已进入抽卡或测试的用户返回首页后保留会话进度，刷新页面后不保存测试答案或用户默想的问题。

## 6. 星座能量世界

### 6.1 范围导航

星座卡下方增加四个范围：

- 今日；
- 本周；
- 本月；
- 本年。

默认打开“今日”。切换范围时仅更新内容区，不重新定位页面，不让卡片高度发生大幅跳动。

### 6.2 今日

展示：

- 总体能量；
- 个人、健康、工作、情绪、出行、好运六维内容；
- 六维百分比；
- 幸运色及色块；
- 幸运数字和幸运字母；
- 宇宙提示；
- 单身建议与伴侣建议；
- 今日适合时段；
- 七日能量趋势。

六维内容默认展示三项，根据用户查看行为或当前能量选择推荐排序，其余三项通过“展开全部”显示。

### 6.3 本周、本月与本年

三个范围都使用相同的六维卡片结构，减少学习成本：

- 顶部摘要和日期范围；
- 六维重点；
- 幸运信息；
- 一条可执行的轻建议。

本月允许查看“当前月”和“下个月”；本年只展示当前年。本轮不生成伪造的月份能量曲线，除非接口实际返回可用于绘制的结构化数据。

### 6.4 继续探索

星座区末尾增加：

- 十二星座今日能量排行；
- 换个星座看看；
- 与当前星座相关的测试或抽卡推荐。

排行必须来自同一日期的结构化百分比；未取齐十二星座数据时不显示排行，不能用本地随机数补齐并标为 API。

## 7. 抽卡实验室

### 7.1 开通前的 Holaday 能量牌

在 DivineAPI 塔罗权限未开通前，体验明确命名为“Holaday 能量牌”，而不是“真实塔罗”。首期内容包括：

- 今日提示；
- 工作推进；
- 关系回应；
- 情绪疗愈；
- 给自己空间；
- 是／否回答；
- 回顾／当下／下一步三张牌。

本地牌库至少包含 36 张独立内容牌，每张具备：标题、副标题、正文、行动建议、适用主题和稳定 ID。三张牌在同一次牌阵中不得重复。

### 7.2 开通后的 DivineAPI 模式

能力表探测到对应权限后，可逐项启用：

- Daily Tarot；
- Yes/No；
- Love；
- Angel；
- Dream；
- Animal；
- Career；
- Past–Present–Future；
- 其他 Gold 牌阵。

不适合 staff 放松场景的成人或高刺激爱情内容默认不进入首页推荐，只能在未来明确分级和确认后开放。

### 7.3 连续体验

每次结果页必须同时提供至少两个下一步：

- 再抽一次；
- 换个主题；
- 进入三张牌；
- 收藏本次提示；
- 查看本次会话抽卡记录。

每日牌同一天保持稳定；其他模式可以重新抽取。同一会话使用已见 ID 集合避免连续重复，牌库耗尽后才允许重新循环。

不保存是／否问题正文，不要求用户输入敏感自由文本。

## 8. 轻测试馆

### 8.1 内容规模

首期包含 6 个主题、每个主题 3 套测试，共 18 套：

1. 情绪电量；
2. 压力节奏；
3. 工作状态；
4. 关系表达；
5. 社交能量；
6. 今日数字。

每套测试包含 5–7 道题、每题 3–4 个选项、4–6 个可达结果。首期总量不少于 90 道题和 72 个结果组合。

测试是娱乐和自我觉察内容，不做医学、心理诊断或人格定性，不使用“患有”“风险等级”等临床化表达。

### 8.2 数据结构

测试题库从组件中拆出，使用数据驱动结构：

```ts
interface LightTestDefinition {
  id: string;
  category: LightTestCategory;
  title: string;
  description: string;
  estimatedMinutes: number;
  questions: LightTestQuestion[];
  outcomes: LightTestOutcome[];
  scoring: LightTestScoringRule;
  relatedTestIds: string[];
}
```

评分规则必须可测试、确定性，并保证每个结果分支可达。

### 8.3 连续体验

结果页提供：

- 换一套；
- 测相关主题；
- 重新测试；
- 收藏结果中的行动建议；
- 返回测试目录。

目录显示已完成状态和预计时长，但不永久保存答案。页面刷新后只保留完成过的测试 ID，不恢复具体选择。

## 9. 等待休息区

页面底部新增“再逛一会”内容区。首期不做无限滚动，使用每组 6 张内容卡和“再来一组”按钮。

首期内容类型：

- 一分钟放松练习；
- 今日幸运签；
- 星座趣味知识；
- 星座关系小问答；
- 今日投票；
- 推荐测试；
- 推荐抽卡；
- 推荐小游戏。

首期至少准备 36 条独立微内容，并按日期、用户已见 ID 和当前能量状态排序。同一会话优先展示未见内容。

内容卡使用统一结构：

```ts
type EnergyContentKind =
  | 'astrology'
  | 'tarot'
  | 'test'
  | 'game'
  | 'micro-content'
  | 'video'
  | 'sponsored';

interface EnergyContentItem {
  id: string;
  kind: EnergyContentKind;
  title: string;
  summary: string;
  estimatedSeconds: number;
  tags: string[];
  source: 'divineapi' | 'holaday-editorial' | 'partner';
  publishedAt?: string;
  expiresAt?: string;
}
```

本轮使用版本化的本地内容目录，不建设后台 CMS。未来增加视频和广告时，迁移为服务端目录而不改变前端卡片协议。

## 10. 任务状态联动

用户从运行中的任务进入今日能量后，页面底部或右下角显示低干扰状态条：

- 正在执行；
- 等待用户操作；
- 已完成；
- 失败。

状态条显示任务名称、运行时长和“返回任务”。任务完成时出现一次非阻塞提醒，并允许用户继续当前测试或抽卡；不强制跳转。

如果当前没有运行任务，不显示空状态条。

本轮复用工作台已有的任务列表／详情状态，不新增轮询协议或任务状态表。若页面无法确定唯一的运行中任务，则显示“查看进行中的任务”而不是猜测某一个任务。

## 11. 未来视频、游戏与广告扩展

### 11.1 视频和游戏

统一内容目录已经支持 `video` 和 `game`。未来内容卡需要增加：封面、时长、播放或启动入口、完成事件和来源信息。

### 11.2 奖励

未来可增加“能量币”，但首期只预留事件和内容类型，不创建余额或兑换账本。未来设计必须满足：

- 奖励来自已完成的视频或小游戏事件；
- 服务端幂等记账，防止刷新重复领取；
- 能量币优先用于主题、装扮和额外娱乐内容；
- 不把观看广告设为使用核心任务执行能力的前提；
- 广告明确标记并设置展示频次上限。

### 11.3 不在本轮范围

- 广告平台 SDK；
- 视频托管和内容审核后台；
- 现金兑换；
- 用能量币购买任务额度；
- 推荐算法或复杂个性化模型；
- 完整内容 CMS。

## 12. 后端与数据流

### 12.1 Provider 能力表

新增独立的能力状态，不再用“有 key”代表所有接口可用：

```ts
type AstrologyCapability =
  | 'daily-horoscope'
  | 'weekly-horoscope'
  | 'monthly-horoscope'
  | 'yearly-horoscope'
  | 'translator'
  | 'chinese-horoscope'
  | 'numerology-horoscope'
  | 'daily-tarot'
  | 'yes-no-tarot'
  | 'past-present-future-tarot';

interface ProviderCapabilityState {
  capability: AstrologyCapability;
  available: boolean;
  checkedAt: string;
  reason?: 'not-configured' | 'not-authorized' | 'invalid-response' | 'provider-unavailable';
}
```

生产运行时不在每次页面打开时全量探测第三方接口。能力状态由配置和受控探测生成，并设置刷新周期；用户请求只调用已启用能力。

### 12.2 成功判定

DivineAPI 响应只有同时满足以下条件才视为成功：

- HTTP 状态成功；
- JSON 可解析；
- `success === 1`；
- 当前端点的必需字段存在且类型正确。

`success: 2`、缺少 `data` 或字段结构不符都进入明确降级，不得返回 `provider: divineapi`。

### 12.3 中文策略

新增英文域和 Translator 域的独立配置：

- 英文内容始终向英文域发送 `lan=en`；
- 中文内容只有在 Translator 能力可用时才向 Translator 域发送 `lan=zh`；
- Translator 不可用时使用 Holaday 本地中文内容并标记来源；
- 本轮不新增模型翻译链路，避免额外成本、延迟和内容偏移。

### 12.4 缓存

- 日运：按日期、星座、语言缓存；
- 周运：按周、星座、语言缓存；
- 月运：按月份、星座、语言缓存；
- 年运：按年份、星座、语言缓存；
- 每日牌：按日期和模式缓存；
- 可重抽牌阵：不得被六小时全局缓存固定为同一结果。

第三方失败时使用最近一次仍在允许陈旧窗口内的成功结果；超过窗口后使用本地内容并显示来源。

## 13. 前端组件边界

建议拆分为以下职责单一的模块：

- `EnergyAstrologySummary`：首页星座摘要；
- `AstrologyWorld`：日、周、月、年范围导航；
- `AstrologyDimensionGrid`：复用六维内容展示；
- `LuckyInsights`：幸运色、数字、字母与关系提示；
- `TarotLab`：模式目录和体验路由；
- `HoladayCardDeck`：本地牌库与会话去重；
- `LightTestLibrary`：测试目录；
- `LightTestRunner`：答题状态机；
- `EnergyExploreFeed`：底部内容组；
- `RunningTaskDock`：任务状态联动。

页面组件只做编排，不继续把题库、牌库、API 转换和体验状态堆在单个文件中。

## 14. 错误和降级体验

- 单个星座范围失败时只降级该范围，其他范围继续可用；
- API 内容不可用时显示“Holaday 本地提示”，不展示技术错误；
- 月运或年运未加载时使用骨架屏，不让整个星座区消失；
- 抽卡请求失败时保留用户所选模式，并允许改用本地能量牌；
- 测试内容是本地确定性资源，第三方故障不影响测试；
- 内容组耗尽后显示“今天先逛到这里，换个体验看看”，并推荐抽卡、测试或小游戏，不出现空白底部。

## 15. 隐私与内容安全

- 不保存塔罗问题正文；
- 不保存轻测试答案；
- 仅保存完成 ID、收藏项、已见内容 ID 和必要的匿名体验事件；
- 星座 API 继续只使用当前能力所需的生日或星座，不把出生地点、出生时间发送到不需要这些字段的端点；
- 轻测试不作医疗、心理诊断或确定性人生判断；
- 关系和牌卡内容使用建议式、娱乐式表达，避免恐吓、宿命论和财务决策指令。

本轮收藏项、完成 ID 和已见内容 ID 使用现有用户隔离的本地存储模式，不新增数据库表，也不承诺跨设备同步。匿名体验事件沿用现有 Energy 事件入口；事件载荷不得包含题目答案、塔罗问题或完整 Provider 文本。

## 16. 分析事件与成功指标

本轮新增或补齐以下匿名事件：

- `energy_section_viewed`；
- `astrology_range_opened`；
- `tarot_mode_started`；
- `tarot_redrawn`；
- `light_test_started`；
- `light_test_completed`；
- `energy_feed_refreshed`；
- `energy_content_opened`；
- `running_task_returned`。

不记录题目答案和默想问题。

上线后重点观察：

- 今日能量会话中位停留时长；
- 每次会话完成的体验数；
- 结果页继续探索率；
- 星座日／周／月／年切换率；
- 底部“再来一组”使用率；
- 任务完成后返回任务的成功率；
- API 降级率和各能力真实来源占比。

首期产品目标是把中位停留时长从约 2 分钟提升到 8 分钟以上，并让至少 35% 的体验完成用户继续进入第二项内容。该目标用于观察，不作为阻止上线的硬门槛。

## 17. 视觉与交互

继续使用当前暖白、亮莓红、薰衣草紫、天空蓝、薄荷绿和阳光黄。新增深度区必须保持：

- 首屏不增加新的大块堆叠；
- 深度内容以范围页签、横向内容轨道和渐进展开组织；
- 抽卡翻面、牌组切换、测试进度和“再来一组”使用活泼但短促的动效；
- 图片使用现有真实资产、Provider 图片或后续生成并落盘的专用资产；
- 不使用 Emoji、CSS 图形、内联 SVG 或占位框代替正式资产；
- `prefers-reduced-motion` 下取消循环、翻转和位移动效，保留即时状态变化。

桌面和移动端都必须保持任务状态入口可达。移动端范围页签可以横向滚动，但不能截断当前选中项。

## 19. 测试与验收

### 19.1 后端

- `success: 2` 不得标记为 DivineAPI；
- 日、周、月、年请求参数与官方契约一致；
- 必需字段缺失时进入正确降级；
- 每项能力可以独立启停；
- 缓存键包含范围、星座、语言和日期范围；
- 未授权塔罗端点不会被用户请求触发；
- Provider 响应中不得泄漏 key、token 或原始错误详情。

### 19.2 前端

- 星座日、周、月、年都可访问；
- 六维内容、幸运信息和来源状态正确显示；
- 抽卡结果后存在可工作的继续路径；
- 三张牌不重复；
- 18 套测试均可开始、完成、重测和切换；
- 所有测试结果分支可达；
- 底部内容组可以刷新且同一会话优先不重复；
- 任务状态条不遮挡主要操作；
- 键盘、焦点、`aria-live`、原生 `title` 和减少动态效果符合现有门禁。

### 19.3 发布门禁

- orchestrator 目标测试、类型检查和构建通过；
- web-workbench 目标测试、类型检查、lint 和构建通过；
- `git diff --check` 通过；
- 已登录桌面视口和窄屏视口完成浏览器验证；
- 真实 API、未授权 API、Provider 故障三种状态都有可复现证据；
- 页面不再把本地内容称为“真实星座提示”或“真实塔罗”；
- 同一会话可以连续完成抽卡、测试和底部内容探索，不出现一次完成后的死路。

## 20. 已锁定决策

- 单卡和三张牌同时建设；
- 本轮采用混合内容补给站，不等待塔罗套餐才扩充页面；
- 当前未授权塔罗使用明确标注的 Holaday 能量牌；
- 星座卡下方增加日、周、月、年和更多幸运／关系内容；
- 页面底部增加可换组的等待休息区；
- 未来视频、游戏和广告使用统一内容协议，但不在本轮接入广告或奖励账本；
- 本轮目标是提升有效停留和放松体验，不使用强制观看或干扰任务返回的机制。
