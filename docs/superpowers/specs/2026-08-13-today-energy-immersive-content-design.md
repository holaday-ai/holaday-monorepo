# HOLA DAY 今日能量沉浸式内容优化设计

## 1. 背景与目标

当前 `/cosmic` 已具备稳定的马卡龙视觉、能量补给、抽卡、轻测试、星座专刊和 36 条“再逛一会”内容。真实用户审计确认，首次进入有吸引力，抽卡与轻测试具备实际内容深度，但页面仍是“高质量入口页”，还不是可以自然连续浏览的内容目的地。

主要问题是视觉承诺与实际交互不一致：

- 6 个 `practice:` 放松练习点击后没有进入练习流程；
- 4 个 `poll:` 投票点击后只有“已打开”状态，没有选项与结果；
- 推荐测试、抽卡和小游戏多次进入同一个通用入口，推荐标题与落地状态不匹配；
- 3 个小游戏推荐实际复用同一个“接住能量”循环；
- 36 条内容连续换 6 组后耗尽，第 7 次直接进入结束状态；
- 移动端内容高度约 8210px，缺少章节定位、续看和回访压缩；
- 生产浏览器曾出现 `energy event report failed`，会影响后续停留与内容效果分析。

本阶段实施方案乙：补齐空交互，并建立跨体验的连续浏览闭环。目标是让真实用户完成一项体验后自然进入下一项，在任务等待期间持续停留 10–20 分钟，同时不以无限滚动、虚假投票比例或焦虑式奖励诱导用户。

## 2. 成功标准

发布前必须满足：

1. 36 条内容入口全部产生可观察的真实状态变化，不存在只改“已打开”文案的空交互。
2. 6 个放松练习、4 个投票、18 套轻测试、3 种抽卡模式、3 个不同小游戏和 4 个星座周期均可到达并安全退出。
3. 推荐卡能打开指定练习、指定投票、指定测试、指定抽卡模式/主题、指定小游戏或指定星座周期，而不是只打开通用目录。
4. 体验结束后提供一个主要“继续下一项”动作和一个次要“返回浏览”动作，用户不会进入死路。
5. 内容池耗尽后进入“换个能量主题 / 继续收藏 / 今日精选重逛”状态，而不是只显示结束文案。
6. 390px 移动端具备章节定位，回访用户首屏压缩，不发生横向溢出；所有主要触控目标不低于 44px。
7. 事件上报失败不阻断用户体验，同时生产浏览器不持续产生 `energy event report failed`；失败必须进入可诊断的受控路径。
8. 尊重 `prefers-reduced-motion`，键盘能够完成所有体验，模态框关闭后焦点返回触发入口。

体验目标：首次用户可以连续完成三项不同体验且每项都获得新反馈；回访用户能在两次操作内继续未完成或进入新的推荐内容。

## 3. 范围边界

### 3.1 本阶段包含

- 练习播放器、投票播放器和游戏模式扩展；
- 推荐目标的结构化路由与精准落地；
- 跨体验“继续下一项”推荐；
- 内容池耗尽后的安全循环；
- 移动端章节导航与回访首屏压缩；
- 今日能量事件上报诊断与去噪；
- 与上述能力相关的状态存储、测试和浏览器验收。

### 3.2 本阶段不包含

- DivineAPI Translator/OpenAI 专用 Key 配置；
- 新购或切换星座、塔罗供应商套餐；
- 视频流、广告接入、广告收益结算；
- CMS、运营后台、UGC、社交评论或排行榜；
- 临床心理评估、医学判断或确定性占卜结论；
- 对首屏马卡龙视觉、现有星座封面体系做整体重设计；
- 支付、规划任务、股票、文件、浏览器、图片或视频模块的行为变更。

## 4. 产品原则

### 4.1 真实互动优先于卡片数量

内容卡只有在产生新信息、新选择或新完成状态时才算“打开”。如果内容只是推荐入口，卡片必须明确标注推荐对象，并精准带到目标状态。

### 4.2 轻松但不空洞

每项体验控制在 30–120 秒内，结束时给出具体可执行反馈。不得用“正在分析”“全网用户都选择”等虚假权威感包装静态内容。

### 4.3 连续浏览但不制造焦虑

“继续下一项”只提供一项推荐，不使用倒计时、连胜惩罚、无限红点或错失恐惧文案。用户随时可以返回页面或退出。

### 4.4 个性化可解释

推荐只基于用户当前选择的能量需求、当天已完成类型、收藏和本次会话已看内容。界面使用“因为你选择了放松”等可理解理由，不使用不可解释的画像标签。

### 4.5 隐私最小化

轻测试答案、抽卡问题、投票选择和情绪正文不发送到事件日志。事件只记录内容/体验 ID、阶段、结果类型、时长桶和成功/失败状态。

## 5. 信息架构与连续体验

页面保留现有顺序，但增加移动端章节导航和上下文续看：

```text
今日能量
├── 今日补给（回访时可压缩）
├── 轻松玩法
├── 今日成长与继续上次
├── 星座专刊
└── 今日内容流
```

完成任一体验后，结果页底部统一显示：

- 主按钮：`继续：{下一项名称}`；
- 次按钮：`返回今日内容`；
- 可选动作：收藏、再来一次或换主题，由具体体验自己提供。

下一项推荐顺序：

1. 优先选择当天尚未完成的体验类型；
2. 优先匹配当前 `energyNeed`；
3. 避免连续推荐相同体验类型；
4. 如果五类成长均完成，推荐收藏内容或新的内容主题；
5. 目标不可用时回退到内容流，不显示失效按钮。

## 6. 结构化目标模型

现有字符串 `actionTarget` 改为可判别联合类型，避免用前缀字符串决定行为：

```ts
export type EnergyContentTarget =
  | { type: 'practice'; practiceId: EnergyPracticeId }
  | { type: 'poll'; pollId: EnergyPollId }
  | { type: 'test'; testId: LightTestId }
  | { type: 'tarot'; mode: 'single' | 'yes-no' | 'three'; theme?: HoladayCardTheme }
  | { type: 'game'; gameId: EnergyGameId }
  | { type: 'astrology'; period: 'daily' | 'weekly' | 'monthly' | 'yearly' }
  | { type: 'astrology-signs' };
```

`EnergyExploreFeed` 只负责内容选择和视觉卡片；`EnergyHome` 把结构化目标交给统一控制器；各体验接收可选的初始目标参数。卡片点击必须由目标控制器返回 `opened` 或 `unavailable`，只有成功打开后才标记已打开与上报事件。

## 7. 体验设计

### 7.1 六个放松练习

新增统一 `PracticeExperience`，纯数据定义 6 项练习：

- 窗边八次慢呼吸；
- 肩颈一分钟松绑；
- 五感回到此刻；
- 一杯水的暂停；
- 桌面三件归位；
- 二十秒远眺轮换。

每项包含 2–4 个步骤、预计时长、视觉主题、简短动作说明和结束反馈。用户可按自己的节奏点击下一步，时间提示不是强制计时；“立即完成”只能在至少展示第一步后使用。完成后计入 `recharge` 成长类型，但单独保存 `completedPracticeIds` 用于续看与去重。

### 7.2 四个真实投票

新增 `PollExperience`，每项提供 4 个本地选项：

- 最有效的休息；
- 专注背景声；
- 完成后的奖励；
- 社交电量。

选择后显示与该选择对应的解释和一个可执行小建议。不得显示伪造百分比；如果以后接入真实聚合数据，再单独增加匿名统计能力。投票允许当天重新选择，并只在本地保存最新选择 ID；事件日志不包含选择内容。

### 7.3 精准轻测试

`TestExperience` 增加 `initialTestId`。从推荐卡或星座关联入口打开时直接展示指定测试的第一题，并保留“返回 18 项目录”。完成后继续支持换一套、测关联主题、重新测试和收藏建议。

### 7.4 精准抽卡

`TarotExperience` 增加 `initialMode` 和可选 `initialTheme`：

- 单张推荐直接进入主题选择，默认单张；
- 是/否推荐直接进入主题选择，明确问题不上传；
- 三张牌推荐直接进入主题选择，默认三张；
- 星座关联入口默认单张 + `uplift`，仍允许用户换主题。

用户在翻牌前始终能确认模式与主题，不能因精准推荐跳过知情选择。

### 7.5 三个不同小游戏

游戏统一由 `GameExperience` 承载，但实现三个不同的交互循环：

1. `catch-energy`：现有 12 轮光点点击，保留键盘操作；
2. `breath-rhythm`：跟随扩张/收缩节奏完成 4 轮呼吸，也提供“按自己的节奏继续”按钮；
3. `color-memory`：观察 3–5 个颜色序列后按顺序选择，最多三轮，不设排名。

三种游戏都无失败惩罚。颜色记忆答错时重复当前轮并降低序列长度；呼吸节奏在 `prefers-reduced-motion` 下使用静态阶段卡代替缩放动画。

### 7.6 星座周期直达

星座推荐卡直接选择今日/本周/本月/本年 Tab 并滚动到专刊。`astrology-signs` 打开十二星座选择器，不修改用户资料；切换只影响临时浏览对象，页面明确显示“临时查看”。

DivineAPI Translator 保持延期。供应商数据不可用时继续显示 `Holaday 本地提示`，但不同周期必须使用周期匹配的本地内容，禁止将今日文本简单复制到本周/月/年。

## 8. 内容流与耗尽状态

36 条内容仍按 6 条一组展示，但“已看”与“已完成”分开：

- 卡片进入真实体验或完成内联内容后才记为已看；
- 推荐卡只在目标成功打开后记为已看；
- 换组不会把未打开内容误记为完成；
- 当前会话避免重复，跨会话可在新的一天重新出现；
- 收藏内容不因内容池轮换而丢失。

内容池耗尽后显示三个明确入口：

1. `换个能量主题`：专注、放松、自信、好心情中选择另一主题，并从该主题的“今日精选”重新排序；
2. `继续收藏`：有收藏时显示；
3. `完成今日能量`：进入成长面板并推荐尚未完成的体验类型。

同一自然日内重新排序可以复用内容，但必须标注“今日精选重逛”，不再声称“没有看过”。日期切换后清理当日会话去重状态，历史完成和收藏仍保留。

## 9. 回访与移动端

### 9.1 回访首屏

当天至少完成一项体验后，Hero 切换为紧凑状态：显示当前能量需求、今日完成 `n/5`、`继续上次` 和“重新选择能量”。用户可以手动展开完整小岛 Hero；次日恢复完整首屏。

### 9.2 章节导航

窄屏增加吸顶章节导航：`补给 / 玩法 / 星座 / 今日内容`。导航只在对应内容进入页面后激活，点击使用平滑滚动；减少动态效果时改为立即定位。桌面端不增加常驻导航，避免与工作台侧栏竞争。

### 9.3 状态恢复

本地进度新增：

```ts
interface EnergyContinuationState {
  dateKey: string;
  lastTarget: EnergyContentTarget | null;
  lastCompletedKind: EnergyCompletionKind | null;
  completedPracticeIds: string[];
  pollSelections: Record<string, string>;
  favoriteContentIds: string[];
}
```

不恢复测试中途答案或抽卡问题；只恢复可公开的体验入口和完成类型。存储解析必须兼容旧版本，非法 ID 被忽略。

## 10. 组件边界

新增或调整以下职责：

- `energy-content-target.ts`：目标类型、校验和推荐目标构造；
- `content-target-controller.ts`：把目标转换为页面滚动或体验启动请求；
- `practice-content.ts`：6 个练习的纯数据；
- `PracticeExperience.tsx`：练习阶段与完成反馈；
- `poll-content.ts`：4 个投票和本地结果文案；
- `PollExperience.tsx`：投票选择与结果；
- `game-content.ts`：3 个游戏模式定义；
- `GameExperience.tsx`：模式路由，具体循环拆到 `games/` 子目录；
- `energy-continuation.ts`：下一项推荐纯函数；
- `EnergyContinueCard.tsx`：继续上次和下一项入口；
- `EnergySectionNav.tsx`：移动端章节导航；
- `energy-progress.ts`：版本化存储、收藏、练习与投票状态；
- `EnergyHome.tsx`：只负责编排，不承载各玩法内部状态；
- `EnergyExploreFeed.tsx`：内容批次、耗尽状态和打开成功反馈。

任何新增组件都不得把练习、投票、游戏、测试和抽卡状态再次堆进 `EnergyHome.tsx`。

## 11. 事件与错误处理

事件模型增加：

- `energy_content_opened`：只含内容 ID 和目标类型；
- `energy_experience_started/completed/failed`：体验 ID、模式 ID、时长桶、结果；
- `energy_continuation_opened`：来源体验类型和目标体验类型；
- `energy_feed_exhausted`：能量主题与当日批次数；
- `energy_section_navigated`：章节 ID；
- `energy_event_delivery_failed`：仅在客户端诊断聚合中计数，不附用户答案。

客户端事件发送改为单一 `reportEnergyEvent()`：

- 网络失败不阻断 UI；
- 相同错误在一个会话只输出一次结构化 warning，避免持续刷屏；
- 使用有限队列重试一次，页面卸载时放弃，不无限重试；
- 4xx 视为不可重试，5xx/网络错误可重试一次；
- 服务端继续执行输入白名单，禁止答案、问题正文和自由文本字段。

目标不可用时，卡片保持未打开状态，并显示可恢复提示“这个体验暂时不可用，已为你保留当前位置”。

## 12. 可访问性与动效

- 所有互动使用原生 `button`、`fieldset`、`legend`、`progress` 或合适的 ARIA 语义；
- 练习和游戏进度使用 `aria-live="polite"`，不得逐帧播报动画；
- 投票结果在选择后获得可感知的标题焦点；
- 颜色记忆同时使用位置/形状标签，不只依赖颜色；
- 模态框遵守 Escape 关闭、焦点圈定和关闭后返回入口；
- 移动端主要按钮最小高度 44px；
- `prefers-reduced-motion: reduce` 禁用浮动、呼吸缩放、卡片翻入和内容换组位移动画；
- 动效仅用于确认选择、完成与内容替换，不增加无意义常驻动画。

## 13. 测试与验收

### 13.1 单元与组件测试

- 结构化目标覆盖所有 36 条内容，未知 ID 解析失败；
- 6 个练习均能完成且不会保存自由文本；
- 4 个投票均有 4 个选项和对应反馈，不包含伪造比例；
- 推荐测试、抽卡、游戏与星座周期精确落地；
- 三个小游戏具备不同状态机，键盘路径可完成；
- 下一项推荐不连续重复类型，并优先未完成类型；
- 内容耗尽状态提供三个可恢复入口；
- 旧版进度数据能够安全迁移；
- 事件失败只 warning 一次，并按错误类型决定是否重试。

### 13.2 集成测试

真实组件路径至少覆盖：

1. 放松卡 → 指定练习 → 完成 → 下一项；
2. 投票卡 → 选择 → 结果 → 返回内容流；
3. 推荐测试 → 指定第一题 → 结果 → 关联测试；
4. 三张牌推荐 → 主题 → 翻牌 → 收藏；
5. 三种小游戏分别完成；
6. 星座本周推荐 → 本周 Tab；
7. 六组内容 → 耗尽 → 换能量主题 → 今日精选重逛；
8. 当日回访 → 紧凑 Hero → 继续上次。

### 13.3 浏览器验收

在生产等价登录态分别检查 1280px 和 390px：

- 页面身份、非空页面、无框架错误覆盖层；
- 首屏、练习结果、投票结果、三个小游戏、星座周期、耗尽与回访状态截图；
- 控制台无相关 error，允许一次明确说明的离线降级但不得持续 warning；
- 页面图片无破图，无横向溢出；
- 键盘完成练习、投票、抽卡、测试和小游戏；
- 减少动态效果模式下无依赖动画才能理解的状态；
- 关闭体验后焦点回到原卡片；
- 移动端章节导航正确定位且不遮挡标题。

## 14. 交付顺序

### 里程碑一：可信互动闭环

- 结构化目标；
- 6 个练习；
- 4 个投票；
- 测试/抽卡/星座精准直达；
- 事件上报修复；
- 36/36 入口真实状态验证。

里程碑一完成后，页面不再存在空心入口，可以独立发布。

### 里程碑二：连续沉浸与回访

- 3 个不同小游戏；
- 下一项推荐；
- 内容耗尽循环；
- 收藏和继续上次；
- 回访紧凑 Hero；
- 移动端章节导航。

两个里程碑在同一方案乙分支实施，但分别提交、测试和浏览器验收，任何一个里程碑都不得用后续工作掩盖自身未通过的门禁。

## 15. 发布与回滚

- 先在独立分支完成两里程碑及浏览器证据；
- PR 默认 Draft，检查和评审通过后再转 Ready；
- 合并、部署必须获得用户明确批准；
- 发布后核对 `/cosmic`、`/api/healthz`、PM2 状态、静态资源和事件错误日志；
- 回滚单位为应用发布提交，不引入不可逆数据库迁移；
- 新本地存储字段全部向后兼容，旧客户端读取时可忽略。
