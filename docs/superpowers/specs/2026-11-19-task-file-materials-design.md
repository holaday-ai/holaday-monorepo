# 仅附件任务的完成契约

此设计落实已确认的原件读取、完整统计、生成文件和读回闭环，便于从已经保存的原件接续。原release-readiness范围、真实站点/账号/KMS/物理验收均保持，不将本组件通过视作Goal完成。

现有普通浏览器执行器始终要求网页证据；纯附件任务即使已经完整处理文件，也会被拒绝，并可能被解释成网页执行未开始。采用现有统一工具循环中的服务端文件契约；不新建浏览器执行系统。实施选择由代理负责，沿用用户已要求的连续串行推进，不新增收费或外部操作权限。

契约只从原用户请求与服务端校验的本任务附件建立：要求明确“仅/只处理、分析或读取所提供附件”，排除网址、域名、正向网页操作、联网搜索、账号/页面/上传/发送请求及混合任务；不从文件正文、模型建议或回复自动升级。缺少已准入附件、关闭功能开关或任务失效时拒绝。

契约由内部不可伪造对象表示，与同一BrowserTaskFiles绑定。只暴露read_task_file、analyze_task_table、create_file、finish；模型自行调用网页、上传、搜索或人工接管工具也不执行。普通网页任务的requireBrowserEvidence及所有既有校验保持原样。

完成前重新验证任务、账号、原始字节和所有生成文件。全部输入与输出须完整读回；请求统计的CSV/TSV须有完整统计，所有已开始的统计不能遗留错误/分页/质量缺口。数值继续绑定现有tableFactId/fileId及原回执，生成文件继续依据真实保存回执。缺少输入或生成文件、错误统计、取消、保存未知、归属或字节改变均不能报告完成。

附件原件的交付采用验证过的文件ID和标准下载路由，不伪装成网站下载回执；生成数量与原件交付分别检查。执行不借用浏览器/登录态，不获取页面来满足无关证明。进度、取消、模型计费记录、任务状态和文件下载继续使用现有回调与服务。

先脚本模型/真实HTTP、隔离SQL及已保存字节验证，再准备真实模型限额请求；当前实际模型额度仍耗尽，未授权前不调用、不扩大守卫。资源保持单fork/文件串行，测试1024–1536MB、类型/构建2048MB，无并行代理、生产写入、合并或上线。
