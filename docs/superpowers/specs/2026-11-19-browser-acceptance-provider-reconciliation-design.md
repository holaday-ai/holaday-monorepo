# 本地验收调用的供应商对账与截止时间

这是已确认浏览器助理计划中“未知结果先核对、禁止自动重放”的实现细节。用户指定当前聊天、单路、低内存和不上线；以下凭证格式与超时值是执行方的技术选择，不称作用户新增的授权。

## 已有事实与边界

14次调用中13次客户端收到响应，1次未收到。既有控制台默认审计已逐笔对应14条，服务端均200；最后一条50.49秒，原中继socket上限45秒、SSH60秒、Node65秒。实际账单未验，模型响应正文不可恢复。原账本、25次上限、原任务未知票据保留。

只调整本地验收工具，不修改产品运行时、生产服务/开关/数据库，不新增密钥、日志投递或外部资源。现有真实站点/账号验收授权继续；此工具本身不扩大访问或费用范围。

## 方式与选择

直接把旧请求改成received会伪造客户端回执，排除。继续永久冻结会丢失已核实的供应商终态。采用固定本机目录的审计凭证，保持旧state=unknown，校验原账本前缀与完整审计内容的哈希、唯一时间/模型/请求号映射和原key身份匹配后，才承认该请求供应商侧已终结。凭证由可信本机核查封存，不是供应商数字签名；网页/模型内容不能提供凭证路径或改写它。

新请求仍受累计25次限制，未收到的旧请求也占用一次；旧未知body即使已有供应商终态也不能重发。新出现且无凭证的未知请求立即冻结。凭证缺失、损坏、歧义或错配均拒绝；不修改旧记录、不重置账本、不清队列票据。

## 部件

- Python纯预算策略：验证凭证、准入、原子保存账本；标准库，无网络。
- Python有总截止时间的HTTP读取：Linux远端使用75秒总期限，响应2MiB上限，无重试/重定向；仅提取request-id与数值用量，不记录正文或凭据。
- 本地中继继续使用原端点/原进程/原身份，SSH95秒、Node105秒，取消后有有界终止。凭证与模块只从固定私有目录读取。
- 正常响应仅在真实收到后标received；审计凭证不会制造响应内容。后续模型调用仍须具体已授权验收任务，测试不发付费探针。

## 验证与后续

先RED再实现。纯策略覆盖缺证、错证、歧义、费用槽位、旧body重放和新增未知；原子写入覆盖替换失败。实际本地HTTP/子进程覆盖迟响应、慢速分片、上限、取消及请求ID/用量留证；不以固定成功回调代替这些边界。

将实际14条审计制作凭证，先运行只读准入/拒绝检查、确认账本字节未改，再接入私有中继。之后继续新的、独立的已授权站点验收，保留原导出和失败证据。完整两站任务、稳定主体、物理输入、AWS/KMS、真实账号生命周期及最终发布绑定仍是完整Goal的必做项。
