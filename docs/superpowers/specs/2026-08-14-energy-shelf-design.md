# HOLA DAY “我的能量架”设计

## 1. 决策与目标

在“今日能量”页面底部增加本地个人内容入口“我的能量架”，用两个标签承载“最近玩过”和“我的收藏”。它解决当前 P2 的剩余用户可见缺口：页面已经能记录当日最后一次体验、内容去重和多种收藏，但用户跨日返回后无法集中找回最近完成的体验，也没有统一查看已收藏能量牌、测试行动建议和杂志内容的入口。

本功能不建设反馈、评分、点赞或跨设备同步。用户已明确取消“有帮助 / 不适合”反馈能力。

成功标准：

1. 用户能在页面底部看到最近完成的体验，并一键重新进入。
2. 现有能量牌、测试行动建议和内容卡收藏能在一个视觉区域中被重新找到。
3. 最近记录最多保留 12 项、30 天；重复体验只置顶，不重复堆积。
4. 不保存测试答案、情绪、生日、出生地或自由文本，不新增服务端接口或数据库。
5. 新区域延续今日能量的马卡龙、插画与轻动效风格，而不是文字历史列表。

## 2. 页面位置与信息架构

“我的能量架”位于 `EnergyExploreFeed` 之后、页面底部任务等待 Dock 之前。它是一个全宽马卡龙容器，不改变首屏、星座专刊或内容流层级。

容器包含：

- 标题“我的能量架”；
- 说明“最近的补给和收藏，只留在这台设备”；
- `最近玩过` 与 `我的收藏` 两个标签；
- 当前标签下的视觉卡片网格；
- 对应的空状态。

桌面端每行展示 3–4 张卡片；窄屏使用单列，避免小字和横向内容裁切。标签切换不滚动页面，不打开独立页面。

## 3. 最近玩过

### 3.1 记录时机

只在体验通过现有 `onExperienceComplete` 成功完成后写入最近记录。开始后退出、加载失败、错误状态和未完成互动不进入历史。

记录覆盖：

- 30 秒补给；
- 一分钟练习；
- 轻测试；
- 抽卡；
- 三个小游戏；
- 通过统一体验容器完成的星座体验。

轻投票当前只保存当日选择，没有完成回调，因此不进入最近记录。星座专刊中的周期切换和十二星座浏览也不是完成动作，不进入最近记录。第一版只记录已经能产生 `onExperienceComplete` 回调的统一体验，不为补齐历史而改变现有产品语义。

### 3.2 排序、去重与保留

- 以完成时间倒序展示；
- 同一标准化目标再次完成时，更新完成时间并移到最前；
- 最多保留 12 项；
- 读取和写入时同时删除超过 30 天的记录；
- 无效、下线或无法解析的目标不展示，并在下一次写入时清理。

最近卡片显示体验类型、标题、视觉、预计时长以及“今天 / 昨天 / M月D日”。有启动目标的项目通过原目标重新进入；无启动目标的项目从对应体验默认入口重新开始。重新进入不预填测试答案，也不恢复已经完成的互动内部状态。

## 4. 我的收藏

收藏标签聚合现有三类本地数据，不复制内容正文：

1. `savedCardIds`：从 `HOLADAY_ENERGY_CARDS` 解析牌名、提示和轻行动；
2. `savedTestActionIds`：从测试 ID 与结果 ID 解析已收藏行动建议；
3. `continuation.favoriteContentIds`：从 `ENERGY_EXPLORE_CONTENT` 解析杂志图片、标题、摘要和目标。

收藏卡优先展示原结果摘要，并提供“再体验一次”主动作。能量牌与测试行动建议需要通过稳定 ID 解析；内容卡继续使用其现有 `EnergyContentTarget`。无法解析或已下线的收藏自动忽略，不展示 ID、空卡或错误占位。

收藏标签增加低噪音的“取消收藏”图标按钮：

- 内容卡复用现有收藏切换逻辑；
- 能量牌与测试行动建议新增对应移除函数；
- 取消收藏不删除完成记录或最近体验；
- 图标按钮必须同时提供 `aria-label` 和原生 `title`。

本阶段不新增星座收藏。`HoroscopeExperience` 现有“星座能量已收藏”结果文案不作为新的收藏数据源；若未来需要可找回的星座快照，应单独设计日期、来源和内容过期规则。

## 5. 本地数据模型与迁移

本地进度从 `holaday.energy.progress.v3` 升级到 `holaday.energy.progress.v4`。现有 v3、v2 和 v1 读取路径保留，首次成功读取后写入 v4。

新增结构：

```ts
interface EnergyRecentExperience {
  experienceId: Exclude<EnergyExperienceId, 'poll'>;
  launchTarget: EnergyExperienceLaunchTarget | null;
  kind: EnergyCompletionKind;
  completedAt: string; // ISO 8601
}

interface EnergyShelfState {
  recentExperiences: EnergyRecentExperience[];
}
```

`EnergyProgress` 新增 `shelf: EnergyShelfState`。收藏继续由现有三个 ID 集合派生，避免同一收藏存在两份状态并发生漂移。

写入边界：

- `experienceId` 必须对应注册表中可完成且可重新打开的体验；
- `launchTarget` 为非空时必须通过现有 `isEnergyContentTarget()` 严格校验，并与体验 ID 匹配；
- 启动目标只允许稳定枚举和 ID，未知字段会被拒绝；
- 当前 `EnergyExperienceLaunchTarget` 不包含自由文本，塔罗只允许 `mode` 和可选 `theme`；
- `completedAt` 必须是可解析时间且不能显著晚于当前时间；
- `kind` 必须与体验注册定义的完成类型一致；
- 读取时重新执行校验、过期清理、去重和上限裁剪。

最近记录的去重键为 `experienceId + 标准化 launchTarget`。例如默认进入轻测试与定向进入“工作专注”测试是两个可区分入口；相同入口重复完成只更新完成时间。

预览模式 `storageScope === null` 继续使用当前窗口级 `WeakMap`，不创建 guest localStorage。登录用户继续按用户 ID 隔离。

## 6. 组件与代码边界

新增：

- `EnergyShelf.tsx`：标签、空状态、卡片编排和用户动作；
- `energy-shelf.ts`：最近记录标准化、收藏解析、展示模型和日期标签纯函数；
- `EnergyShelf.test.tsx` 与 `energy-shelf.test.ts`：交互和纯逻辑测试。

修改：

- `energy-progress.ts`：v4 迁移、最近记录结构、保存和收藏移除函数；
- `energy-progress.test.ts`：迁移、保留、去重、隐私与用户隔离；
- `EnergyHome.tsx`：在体验完成后用当前 `selectedExperience.id` 与 `selectedLaunchTarget` 写最近记录，渲染 `EnergyShelf`，并复用现有 `openExperience()` 与 target controller；
- `EnergyHome.test.tsx`：完成到展示再到重新进入的集成路径；
- `energy.css` 与 `energy-css.test.ts`：马卡龙卡片、响应式、焦点和减弱动画。

`EnergyShelf` 只接收已经解析的展示模型和动作回调，不直接操作 localStorage，不持有玩法内部答案，也不复制 `ExperiencePlayer` 的状态机。

## 7. 视觉与动效

卡片按内容类型复用现有视觉：

- 能量牌：塔罗牌插画与紫粉色；
- 测试行动：轻测试插画与薄荷绿；
- 杂志内容：现有 `allocateMagazineVisuals()` 图片；
- 最近练习、游戏与星座：现有体验图标、星座徽章和对应主题色。

卡片必须包含可识别视觉、标题和一个主要动作，不使用密集时间线。新记录加入时使用轻微上浮和柔和光晕；`prefers-reduced-motion: reduce` 下禁用所有新增动画。

标签使用标准 `tablist / tab / tabpanel` 语义，选中状态不只依靠颜色。键盘可以切换标签、打开卡片和取消收藏。触控目标不小于 44×44 CSS 像素。

## 8. 异常与降级

- localStorage 不可用：沿用当前内存结果，页面和体验仍可使用；
- v4 数据损坏：忽略无法解析的 shelf 项，不让整个今日能量页面失败；
- 内容定义下线：过滤对应卡片；
- 动态体验加载失败：继续由现有 `ExperiencePlayer` 显示重试和返回；
- 取消收藏写入失败：当前会话保持更新，刷新后以实际可读取数据为准；
- 空状态：显示一张低噪音插画和明确下一步，不渲染不可点击的假卡片。

## 9. 隐私与非目标

不得保存或上传：

- 状态签到选择；
- 测试问题、答案或得分轨迹；
- 塔罗自由问题；
- 生日、出生时间、出生地点；
- 用户自由文本；
- 反馈、评分、点赞或“不喜欢”原因。

本次不新增：

- 数据库表、migration 或 tRPC 路由；
- 分析事件或管理后台；
- 跨设备同步；
- 搜索、筛选或批量管理；
- 星座内容快照收藏；
- C 阶段内容运营系统。

## 10. 测试与验收

纯逻辑测试：

- v3 → v4 保留现有完成记录、连续天数和收藏；
- 最近记录按时间倒序、重复置顶、12 项上限和 30 天清理；
- 非法体验 ID、目标与体验不匹配、未知字段、无效日期和 kind 不匹配被拒绝；
- 收藏 ID 能解析成展示模型，未知 ID 被过滤；
- 日期标签覆盖今天、昨天和更早日期。

组件与集成测试：

- 标签语义、键盘切换和焦点状态；
- 最近与收藏空状态；
- 完成体验后出现最近卡片；
- 点击最近卡片通过现有体验注册表与 target controller 重新进入；
- 收藏展示、取消收藏和重新体验；
- 预览模式不创建 guest localStorage；
- 不产生反馈 UI 或额外服务端事件；
- 移动端单列和 reduced-motion CSS 门禁。

交付门禁：

- Today Energy 定向测试；
- Web 全量测试；
- Web lint、typecheck、build；
- `git diff --check`；
- 生产真实用户态验证最近项目、收藏取消、重新进入、控制台和两端 healthz。
