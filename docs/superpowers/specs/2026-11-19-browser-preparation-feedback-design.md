# 网页准备回执与持续反馈

这是已确认上线前方案内的故障修复。功能、站点、账号、费用、低内存串行及不上线边界继续由 `2026-11-18-browser-assistant-release-readiness.md` 约束；本文记录代理的内部实现选择，不增加任何外部权限。

## 已有证据

实际慢页准备先失败，随后准备成功，但任务创建被未知执行保护拒绝。隔离真实 WS/JWT 验证中，旧 token 拒绝再有效登录的未知计数保持零。真实 HTTP/tRPC 复现中，原准备的泛化错误留下未知记录，随后成功没有消除它；保护在业务写入前拒绝。这是应当保留的安全行为，不能按 HTTP 状态推断没有副作用。

创建结果未确认时，乐观任务行仍名为“正在创建任务”，短暂提示消失后缺少持续说明。输入仍保留。

## Approaches

1. 为已确认创建、仅等待加载的页面返回成功的非终态回执，客户端继续核对相同准备编号。需要同步插件、主机和两个客户端，但无需修改全局未知保护。采用此方案。
2. 对旧错误保存主机操作票据，待后续回执到达后按原所有权核销。需要额外的持久化、跨进程关联和核销协议；本次故障不必新增这些生命周期。

## 契约

- 新能力 `task_tab_readiness_v1` 与请求 `reportReadiness` 双向协商。旧客户端不请求时保留旧输出；发现旧服务端/插件时不发送新字段。
- 插件仅在收到 Chrome 创建回执、确认原账号和准备编号仍一致时报告 `taskTabStatus: loading`。回执绑定 preparationId、sourceTabId、sourceOrigin、tabId、taskTabCreated。原始 URL、密码和令牌不离开浏览器。
- 主机验证当前连接、原准备编号、源标签页、站点和浏览器会话。只把合格回执转为 `preparationState: loading`，不发任务/扣额度/调用模型。真正未知的创建、无回执、错账号、错来源、错会话、畸形回执保持原拒绝和未知保护。
- 持久化准备路径只报告已确认的创建和导航。导航发送前的记录不能冒认收到导航回执；私有记录增加可校验的 `navigationAcknowledged`，旧未带该字段的记录继续保守观察。marker 未唯一找到、导航回执缺失或存储未确认时不制造 loading 成功回执。
- 客户端最多核对 3 次，每次等待之间 1000ms，只复用原准备编号、原来源及原账号；仅对有效 loading 回执继续。取得 ready 后才提交任务一次。超过上限保留输入和准备记录，等待后续核对。
- 加载时显示“独立页面仍在加载，正在继续核对…”。创建结果未知时显示“任务创建待核实”，持续说明“创建结果尚未确认，请先核对任务列表，避免重复提交。”；不自动重发未知的任务创建。
- 工作台和侧栏均处理 loading；后台持久化恢复沿用同一 helper，不把 loading 当成已获得操作句柄。

## 保护与兼容

`trpc.ts`、`task-drain.ts`、`webhook-drain.ts` 的全局未知判定和核销规则保持。新发现能力只作 UI 提示，主机每次使用新握手确认。传入权威 selection 前剥离 UI 能力字段；准备和创建的幂等编号保持。

保留真实未知泛化错误的 HTTP 回归，同时增加已确认 loading 的 HTTP 零未知用例。真实 Chrome 验证慢加载、同页恢复、请求次数、原页输入/焦点及私有记录清理。再回到完整真实站点任务，不用合成测试替代账号、KMS、物理或生产身份验收。
