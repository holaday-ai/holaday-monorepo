# HOLA DAY 能力中心功能闭环设计

## 1. 已确认方向

用户确认先以“完整内容版”完成能力中心功能，最终视觉与全站设计系统后续统一优化。本阶段保留以下信息结构，不把 `/skills` 继续做成单纯的开关设置页：

- 一个重点能力及其成果示例；
- 两个次级能力及其成果示例；
- 能力所需材料、交付结果、数据连接与边界说明；
- 全部能力目录；
- 从示例或能力直接进入新任务；
- 原有启用、停用和套餐上限能力。

本阶段前端达到清晰、可用、响应式和可访问的上线基线，但不把当前 Image Gen 视觉稿当作最终像素验收目标。高级感、科技感、统一字体、颜色、动效和组件皮肤留到全站视觉收口阶段。

## 2. 产品目标

把 `/skills` 从“技能开关列表”升级为“能力发现与任务启动中心”。用户进入页面后应能完成三件事：

1. 看懂 Holaday 当前真实支持什么；
2. 通过示例理解需要提供什么、会得到什么以及能力边界；
3. 选择示例后进入新任务编辑器，检查并修改请求，再主动提交。

能力中心不得自动提交任务，不得把静态示例冒充真实执行结果，也不得把“需要某连接器”显示成“用户已经连接”。

## 3. 信息架构

```text
能力中心
├── 重点能力
│   ├── 能力名称、说明和成熟度
│   ├── 示例结果预览（明确标记“示例”）
│   ├── 示例任务
│   └── 用这个能力 / 启用并使用 / 查看套餐
├── 两个次级能力
│   ├── 一句话价值
│   ├── 示例结果摘要
│   └── 查看并使用
├── 当前能力详情
│   ├── 你需要提供
│   ├── 会交付什么
│   ├── 执行时可能调用的数据或工具
│   └── 边界说明
└── 更多可完成的事
    ├── 搜索
    ├── 内容运营
    ├── 分析决策
    └── 管理协作
```

重点能力默认使用 `data-report-insight`；两个次级能力默认使用 `social-media-strategy` 与 `contract-risk-review`。如果目录缺少预设能力，则按服务端返回顺序安全降级，页面不能崩溃。

## 4. 能力目录数据契约

`packages/shared-types/src/skills.ts` 是能力真相源。每项 `HoladaySkill` 增加：

```ts
interface SkillExperience {
  starterPrompts: readonly [string, string, string];
  requiredInputs: readonly string[];
  deliverables: readonly string[];
  boundary: string;
  exampleSummary: string;
}
```

每项 `HoladaySkill` 通过 `experience: SkillExperience` 挂载该内容，避免执行元数据与展示内容散落在多个前端文件。

这些字段随 `skills.list` 返回给前端。它们描述产品能力，不表示任务已经执行，也不表示第三方连接已经由当前用户授权。

内容规则：

- 示例请求必须可编辑，并与对应技能真实范围一致；
- `requiredInputs` 只写用户为提高结果质量可提供的材料；
- `deliverables` 不承诺无法保证的文件格式或自动发布动作；
- `boundary` 明确法律、金融、事实核验、平台授权或人工复核边界；
- 连接器区域使用“执行时可能调用”，不得显示未经核实的“已连接”。

## 5. 任务启动流程

```text
用户点击示例
├── 技能已启用 → 生成带 skillId 的可编辑草稿 → 进入首页编辑器
├── 技能未启用且套餐有空位 → 调用 skills.toggle 启用 → 生成草稿 → 进入首页编辑器
└── 技能未启用且套餐无空位 → 不跳转 → 显示套餐或上限提示
```

草稿格式：

```ts
{
  skillId,
  skillName,
  skillSource: 'manual',
  prompt: `@${skillName} ${starterPrompt}`,
}
```

首页 `InputArea` 继续负责消费 `location.state.skillTaskDraft`、选中技能并聚焦编辑器。能力中心不绕过现有 `tasks.create` 的服务端技能启用校验。

## 6. 页面状态

- 加载：保留统一 `PageLoadingPanel`；
- 加载失败：保留重试和联系支持；
- 空目录：保留诚实空状态；
- 搜索无结果：显示“没有匹配的能力”，但保留清除搜索操作；
- 保存中：同一时间只允许一个启用状态请求；
- 套餐上限：禁用新增能力，并提供查看套餐入口；
- 已启用能力：可直接使用，也可从目录停用；
- 服务端返回不同状态：服务端结果覆盖乐观状态。

## 7. 响应式与可访问性

- 桌面内容宽度沿用 `PageContainer width="wide"`；
- 1024px 以下重点能力与详情纵向排列；
- 640px 以下所有能力区块单列；
- 交互目标不小于 40px，核心 CTA 不小于 44px；
- 示例选择、启用状态和当前能力不能只靠颜色区分；
- 能力切换使用原生按钮并提供 `aria-pressed`；
- 保存状态使用 `aria-busy`；
- 示例预览明确写“示例”，避免被理解为用户真实数据。

## 8. 本阶段不做

- 不制作最终高级科技感皮肤；
- 不新增第三方连接授权流程；
- 不新增能力商店、付费单项能力或下载能力；
- 不自动提交任务；
- 不修改技能套餐价格或服务端套餐上限；
- 不修改 orchestrator 的任务执行、验证或计费逻辑。

## 9. 验收标准

1. 13 项能力均由服务端目录返回完整体验字段，畸形字段前端安全降级。
2. 用户能从重点能力、次级能力和全部能力目录选择示例并进入可编辑的新任务草稿。
3. 未启用能力会在有额度时先启用再进入草稿；无额度时保持当前页并给出准确提示。
4. 页面展示所需材料、交付内容、可能调用的连接器和边界说明，不声称连接已经完成。
5. 搜索、切换能力、启用/停用、错误、空状态和窄屏布局均可用。
6. Web 全量测试、相关 orchestrator 测试、类型检查、lint、构建和浏览器核心流程验证通过。
