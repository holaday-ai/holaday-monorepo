# HOLA DAY 股市任务 P1B：任务型工作台信息架构设计

**日期：** 2026-08-18  
**状态：** 已确认方案乙，待实施计划  
**基线：** `claude/musing-keller-ae1d05@027c9f38`  
**范围：** 仅重排和压缩现有股市任务前端体验；不改变行情、风控、筛选、画像或简报的事实口径。

## 1. 背景与问题

股市任务已经具备可信日期、发现、自选股行情、风险雷达、条件选股、偏好画像、每日简报和市场背景，但生产页面仍按“资讯门户”组织：首屏先展示发现和市场信息，用户真正要处理的自选股风险、条件选股和偏好画像位于长页面下方。

2026-08-18 的生产审计确认了三个结构问题：

1. “发现”占据首屏主位，核心任务入口被推后；
2. 页面使用一个贯穿全页的 `主列 + 320px 侧栏`，侧栏内容结束后右侧持续空置，风险、选股和画像被压缩在左侧窄列；
3. 风险按事件逐卡平铺，同一股票重复出现；画像把摘要与全部依据同时展开，浏览效率低。

数据新鲜度仍是不可退让的 P0：任何布局变化都必须保留真实数据日期、来源状态、历史/不可用降级和快照绑定，不得用视觉重排掩盖过期数据。

## 2. 用户目标

用户进入股市任务后，应按这个顺序完成判断：

1. 先确认数据是否为当前或最新可用交易日；
2. 快速看到自选股发生了什么、哪些事项需要继续核对；
3. 按自己明确的条件寻找股票，并区分符合、不符合和缺少数据；
4. 看见自己的研究偏好、优势与盲点；
5. 最后再浏览新闻、行业、榜单等市场背景。

本页面不判断用户是否“适合买入”，不生成推荐指数，不推断风险承受能力，也不触发交易。

## 3. 设计原则

- **任务优先：** 自选股、风险和条件选股排在资讯之前。
- **信任先于内容：** 日期、来源、降级状态和证据不因压缩布局而弱化。
- **先摘要、后依据：** 默认展示可行动结论，完整事实和证据按需展开。
- **不重复解释：** 同一股票的多条风险先聚合，再查看事件明细。
- **不增加请求：** 复用现有查询、轮询、快照和客户端状态，不新增数据库或后台接口。
- **安静刷新：** 后台更新不改变滚动位置、焦点、筛选结果或用户已展开的内容。

## 4. 信息架构

页面从上到下调整为五层。

### 4.1 可信页头

保留当前标题、来源状态、数据日期、刷新时间、手动刷新、生成日报和日报开关。动作在桌面端保持单行；窄屏允许有序换行，但数据状态始终与标题相邻。

历史、延迟、不可用和未核验状态继续使用现有 `stockDashboardTrustState` 与 `stockTemporalCopy`，不新增另一套日期判断。

### 4.2 股票任务输入

保留当前问题输入与快捷任务。它仍位于页头之后，但视觉高度收紧，避免输入区与首个任务模块争夺首屏。

快捷任务只使用与当前可信状态相符的时态；不可用或未核验时继续禁止创建带行情事实的股票任务。

### 4.3 我的股票工作台

这是新的主区域，替代当前贯穿全页的 `main + aside` 布局。

顺序为：

1. **我的关注：** 复用现有 `MarketHighlights`，显示真实关注数量、行情、走势图、日报状态和编辑入口；
2. **自选股风险雷达：** 使用全宽容器，按股票聚合风险；
3. **研究工具：** 桌面端为 `条件选股 7/12 + 偏好摘要 5/12`，小于 1024px 时变为单列；
4. **今日关注日报：** 复用现有证据与快照生成逻辑，承接前面三个模块的结果。

研究工具的两列只用于空闲态和条件确认态。条件选股出现结果后，筛选结果占满整行；偏好摘要移动到结果下方，避免 20 只深查结果被挤进窄列。`StockScreeningWorkbench` 通过一个只读的布局状态回调通知页面 `idle / criteria / results`，不改变筛选请求或结果数据。

### 4.4 市场背景

原“发现”、市场行情、明星股票、市场温度、行业趋势和榜单统一放到核心任务之后，并使用独立的响应式网格，不再让 320px 侧栏贯穿整页。

- “发现”对用户显示为“市场动态”；
- 默认标签按确定性相关性选择：有自选股新闻时优先“自选股新闻”，否则依次选择“重要公告”“A股要闻”“全部”；
- 仅当新闻明确携带关注股票代码时显示“与你的关注相关”，不使用画像或弱行为猜测相关性；
- 市场行情、明星股票、市场温度、行业趋势和榜单作为背景资料，不使用“建议”“机会股”等推荐表达。

桌面端采用以下布局：市场动态占 8/12，市场温度、行业趋势和榜单组成 4/12 背景列；行情与明星股票在下一行各占一半。小于 1024px 时全部单列。

## 5. 组件变化

### 5.1 `StockTasksPage`

- 移除贯穿全页的 `xl:grid-cols-[minmax(0,1fr)_320px]`；
- 明确拆分 `StockTaskWorkspace` 与 `MarketContextSection` 两个布局区；
- 保留现有数据加载、20 秒后台刷新、single-flight、防旧数据覆盖和快照绑定；
- 新增筛选展示状态，仅控制布局跨度，不改变筛选条件或请求参数；
- 所有 Sheet、新闻弹窗、自选股编辑和任务跳转行为保持不变。

### 5.2 `StockRiskRadar`

客户端按 `symbol` 聚合 `signals`：

- 股票组以最高严重度作为组级标签，严重度顺序为 `高风险 > 警示 > 关注`；
- 组级摘要显示股票名、代码、事件数量、最高严重度和最近事实日期；
- 默认展示最多两条事件摘要；其余事件由“查看全部 N 条”展开；
- 每条事件仍保留事实、为什么相关、规则、来源、抓取时间、证据编号和原文链接；
- 排序为最高严重度、最近事实日期、稳定股票代码，确保刷新后顺序可解释；
- `checks` 中无法判断的项目继续单独展示，不并入已触发风险。

聚合只影响展示，不去重或修改服务器返回的事实。

### 5.3 `StockScreeningWorkbench`

- 新增 `onViewStateChange(state)`，状态仅取 `idle / criteria / results`；
- 识别条件后进入 `criteria`，成功、零结果或部分结果均进入 `results`；
- 清空条件返回 `idle`；
- 请求失败不清除上一次可信结果，错误就近展示；
- 当前符合/缺失/未满足、数据日期、证据与非建议声明全部保留。

### 5.4 `StockPreferenceProfile`

新增 `presentation="compact" | "full"`，默认保持 `full` 以避免影响其他调用；股市任务页面使用 `compact`。

紧凑态包含：

- 置信度、90 天样本量和主动设置数量；
- 最多三条偏好事实；
- 一条主要优势、一条主要盲点和一条补充视角；
- “查看完整画像”入口，在 Sheet 中展示现有完整内容；
- 刷新、暂停、恢复、调整和清空能力保持可用。

选择摘要时使用服务端既有顺序，不在前端重新解释或评分。

### 5.5 `DiscoveryPanel`

- 视觉标题改为“市场动态”；
- 首次加载时按确定性相关性选择默认标签；用户主动切换后，后台刷新不得抢回默认标签；
- 关注相关标签只由明确股票代码交集产生；
- 翻页、加载更多、原文链接、公告/新闻数量和发布时间保持不变。

## 6. 状态与错误处理

### 当前数据

正常展示全部任务区和市场背景；后台刷新只更新数据，不重置展开状态、筛选结果、新闻标签和滚动位置。

### 延迟或历史数据

保留真实日期和现有历史语态。风险与选股使用被快照允许的只读能力；任何“今日”“最新”字样必须由 `stockTemporalCopy` 决定。

### 不可用或未核验

不展示旧数值冒充当前事实。风险雷达和条件选股进入明确不可用状态；画像作为历史研究习惯仍可查看和管理；市场背景只展示有日期与来源的可核验内容。

### 部分失败

单个模块错误停留在模块内，其他模块继续可用。页面级错误条只用于多个核心数据源同时失败或无法建立可信快照。

### 加载

页头和输入区先出现；工作台使用与最终尺寸接近的骨架。风险和画像独立加载，完成时不让页面整体跳动。状态播报使用现有可访问名称，并避免轮询重复播报。

## 7. 响应式与可访问性边界

本轮保证新布局不破坏现有响应式规则，但不把完整 P2 验收混入本 PR。

- `>= 1024px`：使用 12 列任务区和市场背景区；不允许核心模块被长期压在半宽主列且右侧空置；
- `< 1024px`：所有核心模块按任务顺序单列；
- `390px`：标题、状态、输入和主按钮不遮挡，横向信息允许换行，不允许水平页面滚动；
- 所有图标按钮保留 `aria-label` 与原生 `title`；
- 展开控件使用原生 button、`aria-expanded` 和稳定焦点；
- 后台刷新不抢焦点，Sheet 关闭后恢复到触发按钮；
- 动效仅用于加载和明确状态变化，并遵守 `prefers-reduced-motion`。

完整的键盘、读屏、缩放、触控目标和真实性能测量仍作为独立 P2 验收任务。

## 8. 数据与隐私边界

- 不新增数据库表、迁移、环境变量或后台路由；
- 不改变 AkShare、快照、缓存、风控、筛选和画像聚合逻辑；
- 不把新闻点击、停留或浏览顺序写入偏好画像；
- 不记录自然语言筛选原文到画像；画像继续只保存有界主动设置和确定性行为信号；
- 不新增投资建议、适当性判断、收益预测或自动交易能力。

## 9. 测试策略

### 单元与组件测试

1. 页面模块顺序锁定为可信页头、输入、关注、风险、研究工具、简报、市场背景；
2. 风险按股票聚合、最高严重度、稳定排序、展开与证据保留；
3. 筛选 `idle / criteria / results` 状态回调和失败后结果保留；
4. 画像紧凑态的摘要上限、完整 Sheet、暂停/恢复/调整/清空；
5. 市场动态默认标签、用户切换保持和明确股票代码相关标签；
6. 当前、历史、不可用和部分失败文案不回归；
7. 图标按钮的 `aria-label`、`title`、展开状态和焦点恢复。

### 回归门禁

- Web 聚焦测试；
- Web 全量 Vitest；
- Web lint、TypeScript 和生产构建；
- `git diff --check` 与触及文件格式检查；
- 不需要数据库迁移验证，但必须确认部署脚本仍通过既有 schema gate。

### 浏览器验收

- 生产同账号、真实数据、1280px 桌面路径；
- 390px 窄屏布局检查；
- 当前、历史/延迟和不可用三类可信状态；
- 风险分组展开、条件识别与真实筛选、画像完整 Sheet、市场动态标签切换；
- 后台刷新跨越至少一个 20 秒周期，确认滚动、焦点、展开项和筛选结果不被重置；
- 两个生产健康端点与双节点 bundle 一致。

## 10. 上线验收标准

1. 在 1280px 桌面端，核心任务区使用完整内容宽度，不再出现核心模块只占左半屏、右侧长期空白；
2. 用户无需先滚过市场动态即可到达关注、风险和条件选股；
3. 同一股票的多条风险只出现一个股票组，组内事件和全部证据可访问；
4. 偏好画像默认可在一个桌面视口内完成摘要浏览，完整依据仍可查看；
5. 条件选股出现结果时自动扩为全宽，不裁切条件、结果或风险提示；
6. 市场动态位于核心任务之后，并优先展示明确相关的自选股新闻；
7. 数据日期、来源、快照、历史/不可用状态和合规边界与当前生产版本一致；
8. 不增加网络请求数量，不引入数据库、后端或生产配置变化；
9. 自动测试、构建和真实生产浏览器验收全部通过后，才能称为本轮完成。

## 11. 发布与回滚

本轮以一个前端主 PR 交付，按组件拆分提交，先完成风险分组和紧凑画像，再完成页面重排与市场动态相关性，最后做响应式和状态回归。

部署目标仅为 `application`。发布前后均核对生产分支提交、双节点 bundle、两个健康端点和真实账号路径。若核心任务入口、日期状态、筛选结果或滚动稳定性任一回归，立即回滚该前端 PR；后端数据和已有画像不需要回滚。

## 12. 明确不在本轮

- 新的证券数据源或选股规则；
- 投资推荐、评分、组合建议或交易；
- 新的画像推断维度或弱行为学习；
- 视频、游戏、广告或跨产品导流；
