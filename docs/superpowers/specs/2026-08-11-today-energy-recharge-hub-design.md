# HOLA DAY 今日能量补给站设计

## 1. 已确认方向

用户已选择第三套“互动补给乐园”方向，并明确要求：

- 整体颜色比初稿再亮一点，避免暗紫、深蓝、深青大面积压住页面；
- 页面要有更多活泼互动与动效，而不是只把静态卡片换颜色；
- 板块要明显比 B 版丰富，但仍服务 Staff 的工作间隙，不变成喧闹的游戏大厅；
- 星座能力必须使用真实 API，不能继续把本地规则结果包装成真实星盘或流年。

## 2. 产品目标

把 `/cosmic` 从“安静的情绪问卷”升级成每天值得回来一次的“能量补给站”。用户应在进入页面 30 秒内：

1. 选择此刻最需要的能量；
2. 完成一次有明显过程反馈的补给；
3. 获得一个轻量结果、当天行动建议和成长反馈；
4. 可继续进入塔罗、小游戏、轻测试或星座内容。

成功不是卡片数量增加，而是用户能感知“选择前 → 补给中 → 完成后”的状态变化。

## 3. 首页信息架构

```text
今日能量 + 当前日期
├── 能量补给舱 Hero
│   ├── 今天想补哪一种能量？
│   ├── 专注 / 放松 / 自信 / 好心情
│   └── 开始 30 秒补给
├── 今天三选一
│   ├── 抽一张今日卡
│   ├── 玩 2 分钟小游戏
│   └── 做一个超短测试
├── 能量成长
│   ├── 连续补给天数
│   ├── 本周点亮轨迹
│   └── 已收集能量胶囊
└── 星座补给
    ├── 今日运势
    ├── 本周运势
    ├── 最佳工作时段
    └── 完善星象资料 / 进入星座详情
```

不展示伪造的“已有 109 位同事完成补给”。没有真实聚合统计之前，社交证明从实现稿移除。

## 4. 核心交互

### 4.1 能量选择

使用新的 `EnergyNeed`：

```ts
type EnergyNeed = 'focus' | 'relax' | 'confidence' | 'uplift';
```

四个选项互斥，必须有 `aria-pressed`。选择后同步更新 Hero 副标题、推荐结果和主按钮说明。默认推荐“专注”，但不在无操作时上报用户状态。

### 4.2 30 秒补给

新增独立 `recharge` 体验，不把主按钮伪装成另一个玩法入口。流程为：

```text
intro → 选择能量 → 3 段呼吸/点亮节奏 → complete → 点亮今日节点
```

用户可跳过自动节奏并立即完成；不强制等待完整 30 秒。完成后显示一条与 `EnergyNeed` 对应的轻行动建议，并更新本地成长记录。

### 4.3 首个小游戏

把 `games` 从 coming-soon 变为 active，首个游戏为“能量点亮”：

- 12 个短回合，每回合高亮一个目标；
- 支持鼠标、触控、Enter/Space；
- 约 60–120 秒完成，可随时退出；
- 不设排行榜、体力、惩罚或付费；
- 结果只给轻反馈和一次成长点亮。

### 4.4 成长记录

记录按用户 scope 保存在本地，只保存日期和完成类型：

```ts
interface EnergyProgress {
  completedDates: string[];
  collectedKinds: Array<'recharge' | 'tarot' | 'game' | 'test' | 'horoscope'>;
}
```

不保存情绪明细、测试答案、塔罗问题或自由文本。连续天数按本地日期计算；同一天重复完成不重复增加天数。

## 5. 星座与 DivineAPI 边界

本轮接入并展示四项真实能力：

1. `daily-horoscope`：已有，继续用于今日运势；
2. `weekly-horoscope`：新增，用于本周运势；
3. `daily-tarot`：已有，用于今日卡；
4. `yes-or-no-tarot`：新增，用户默想问题后按需调用，不上传问题正文。

本轮不接入真实本命盘和行运。官方 Natal/Transit 接口需要精确经纬度、出生时间、时区以及额外资料；在地点标准化与隐私同意完成前，不再显示由生日哈希生成的“月亮倾向、上升倾向、流年提醒”。相关入口改为诚实的资料完善说明。

服务端默认 Horoscope/Tarot host 更新为官方 `astroapi-5.divineapi.com`，同时保留环境变量覆盖和本地确定性降级。非英文翻译 host 独立配置；未配置翻译能力时不得谎称 provider 已返回中文。

## 7. 动效规格

- 页面进入：Hero、三选一、成长/星座区依次以 60ms 间隔淡入上移，单段 360ms；
- Hero 岛：6s 轻浮动，位移不超过 8px；
- 环绕能量：8–14s 缓慢轨道运动，透明度低于 0.65；
- 主按钮：2.8s 柔和光环呼吸，hover 上移 2px，按下缩放到 0.98；
- 能量选项：选择时 220ms 弹性缩放，图标旋转不超过 8deg；
- 体验入口：hover 上移 4px，插画轻微位移；
- 成长节点：完成后按 90ms 间隔依次点亮；
- 结果反馈：短暂柔光扩散，不使用满屏彩屑。

`prefers-reduced-motion: reduce` 时取消循环、轨道、弹性和位移动画，只保留即时颜色与透明度变化；功能和反馈不能依赖动画才能理解。

## 8. 响应式与可访问性

- 桌面设计基准：1440×1024，内容宽度约 1180px；
- 900px 以下 Hero 变两行，三选一改两列；
- 640px 以下所有主区块单列，Hero 插画不遮挡文案和 CTA；
- 交互目标不小于 44×44px；
- 键盘顺序与视觉顺序一致；
- 选中、完成、禁用状态不只靠颜色；
- 动态结果使用克制的 `aria-live="polite"`；
- 图片具备描述性 `alt`，纯装饰图使用空 `alt`。

## 9. 验收标准

1. 生产截图同视口对比时，首屏明显更亮、更有主焦点，且没有大面积暗色块。
2. 能量选择、30 秒补给、三项体验、成长记录、今日/本周星座均可从首页完成或进入。
3. 小游戏具备完整开始、进行、完成、重玩和退出流程。
4. 页面至少包含五类可感知微动效，并完整支持减少动态效果。
5. 不展示伪社交数据，不把本地规则标成真实星盘/流年。
6. 目标测试、类型检查、lint、构建、桌面和窄屏浏览器验证通过。
7. `design-qa.md` 使用选定视觉稿与实现截图同视口比较，最终结果为 `passed`。
