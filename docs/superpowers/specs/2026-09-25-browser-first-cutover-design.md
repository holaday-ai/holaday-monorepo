## 0. 首次旧版不可观测请求：受控中断修订（2026-09-28 已确认）

### 0.1 选择及真实代价

目标仍是完成原浏览器首次切换，不再要求旧版提供不存在的全量内存排空接口。选择一次性、明确记账的受控中断；不选择继续无限等待“健康检查/数据库空集证明内存空闲”，也不先重发旧版补丁（补丁本身仍需首次重启）。普通升级的排空协议完全不变。

接受的风险仅为：已核实旧进程内无法枚举的请求可能在维护时中断，可能未落库、未返回结果，也可能已经触发外部操作。**无法承诺这些请求没有丢失、没有副作用、都能被找回或恢复。** 数据库无活动记录不消除该风险；本方案也不承诺零损失切换。

此风险不是支付豁免、不是未知写入源豁免，也不是让已知未完成任务自动归零。未知来源进程/写入者、无法隔离的浏览器会话、已识别且结果不明的外部操作、活动任务及子记录、未释放租约仍阻断。支付不明仍阻断，仅保留第 1 节已批准的精确九笔支付宝及单笔 PayPal 延期，不扩大指纹集合或访问 PayPal。

支付检查的覆盖范围必须独立成立：不得把支付通道本身的观测缺口归入此范围级风险；若不能按原门槛核对旧支付请求及恢复路径，则仍停止切换。此修订没有证明不存在未落库支付，也不以查到的订单集合为空声称支付安全。

### 0.2 首次停止前后分别证明什么

1. 沿用受保护的候选、配置、全部迁移、双机进程/入口清单及绝对维护窗口；新增风险批准引用仅对本次 attempt、旧源摘要、清单摘要和候选有效，不用可复用的 `ALLOW_UNKNOWN=true` 开关。窗口过期、身份或清单变化不能沿用。
2. 新任务/新订单入口及旧连接的继续派发入口必须实际阻断。既有连接不是天然排空；若将其关闭，也属于本次中断，须明确覆盖在已批准入口范围内。原支付回调在准备阶段仍按第 5 节工作，进入停写前才做完整隔离。
3. 停止前采集新鲜持久工作、支付、实际进程和启动源事实，记录不可观测的范围。仅当所有**可识别的阻断项**均核清时，才允许以受控中断替代旧内存零请求证明；等待时长或空 TCP 连接数不能创造这一批准。清单给出观察截止及已核实的停止超时，截止到达不自动扩大允许范围。
4. 原生产者优先、精确进程身份核验、PM2 单对象停止例外及注册移除规则保持不变。不能连带停止共享 daemon、无关站点或未批准的 headed browser/VNC；若它们可能继续执行本次旧任务，必须先核清归属和隔离，否则停在该门槛。
5. 生产者停止后重新检查持久工作，覆盖停止前后新增任务、子记录、租约及现有重派发来源。出现活动或未知持久记录，保持隔离并处理阻塞，不能标记失败/完成以便放行。候选启动恢复路径不得自动重放旧的不确定请求；恢复源无法分辨时，阻断启动/开放而非删除队列。
6. 备份前仍须独立证明所有相关旧进程、后代、监听、自动重启及内部/外部数据库写入通道已停止或隔离，并验证完整物理退出。这证明的是**数据库不会被旧来源继续写入**，不是互联网另一端没有尚在完成的历史操作。未知写入者不在接受风险内。

### 0.3 不把风险记录伪装成排空证明

复用原受保护清单、主机锁、journal 和 readiness 报告，不新增队列、任务系统或通用运维平台。首次路径最小扩展如下：

- 严格排空路径保留 `legacy_settled`。中断路径使用独立 `legacy_interruption_accepted` 阶段再接原 `producers_stopped`，不写“全部排空”的旧回执。必须先持久记录中断意图与范围，再发送一次停止；应答丢失只观察，不能自动重发。
- 明确区分“观察到零”“观察到非零”“旧版不提供观测”。`activeRequests` / `externalWork` 的旧版不可观测值保留为未知及原因，不把 `null`、缺字段或采集失败转为零。只有已核实的旧版能力缺口可走风险分支，权限/连接/解析失败仍是失败。
- 残余风险记录包含绑定摘要、来源/时间、不可观测范围、批准引用、停止事实引用、禁止重放约束、负责核对者及截止时间；已知对象用私密证据引用。无法枚举的旧请求只记范围级未知，不编造逐条任务或数量，不保存密钥及业务正文。
- 残余风险摘要贯穿备份、候选种子、新 bootId 的首次报告及最终交付；不能随进程退出、检查通过或日志阶段推进而删掉。使用显式的新首次协议版本；未知版本、旧消费者忽略风险字段或缺失绑定均拒绝，普通维护报告不接受该例外。
- `facts.observeWork`、site 边界检查、host 停写检查和首次 readiness 必须一致区分旧残余风险与当前可观察工作；禁止仅在某一层替换四个计数为零，或返回空数组掩盖未核验事实。物理停写与支付仍由原独立检查提供证据。

### 0.4 新候选关闭启动与开放

首次种子只表示新的执行代际开始，不能证明旧请求没有副作用。原目标状态目录检查、既有 dirty/锁不覆盖、真实新 bootId、候选 closed/idle、候选 `needsReconciliation=false` 及 worker 未启动的要求均保留。新候选自身不确定工作不能归入旧风险；其 clean 只描述新代际，首次报告必须同时展示继承的残余风险。

开放前，不要求再次证明不可枚举的旧内存请求总数为零，否则只是换名保留不可能前提。满足其余全部 readiness 后，**仅范围级、未能识别具体请求的旧残余风险**可以仍为“接受风险、结果未知”并随候选开放；不称为“已核清”。已识别的未解决任务、外部效果或支付仍阻断，只有原精确历史支付延期例外继续适用。实际停写备份、隔离恢复、完整迁移和非 PayPal 恢复证据不可由风险批准替代。

维护期间新发生的支付仍遵守第 5、6 节既定重投/查询及开放后核对安排；不要求提前收到未来事件，也不增加“仅支付开放”模式。原应用 open 会同时允许内部生产者，故全部当前门槛满足后才能 open。

### 0.5 不确定结果如何收尾

部署执行者按清单担任核对责任人，在既定截止前汇总新证据、实际中断事实与未能识别的残余风险；时间到达本身不能把未知改成已解决，也不要求无限等待虚构的零值。最终发布报告允许写“按已接受的首次中断风险完成切换”，不得写“旧工作全部无损完成”。

发现具体未决外部动作后先只读核对，不自动重试、重新派发、补扣款或改业务状态；确需业务补偿则另行明确对象和授权。开放前发现则阻断；开放后发现则按原失败机制重新关闭接单，保留同实例实际状态和证据，不自动回滚旧库/旧程序。无法枚举的请求没有可展示的逐任务状态，不编造成功结果或批量改历史任务；用户报告个案时按其证据核对，不据“旧库无记录”建议重复提交外部动作。

### 0.6 必须新增的验收与覆盖范围

在原固定验收内加入：严格排空与受控中断两条首次路径；未知值/故障/非零值不能混淆；批准/窗口/目标/风险摘要/协议版本漂移拒绝；未知写入者、活动子记录、已知未决外部操作及非豁免支付拒绝；实际 Linux 旧进程中断与入口/物理停写验证；新候选不自动重放旧请求、不抹掉残余风险；新候选 dirty 仍拒绝；停止/open 应答未知保持单次操作。完整成功与故障演练仍是上线前置，不以局部单测替代。

本节已获书面确认，只覆盖第 1 节旧“未知工作仍拒绝停止”、第 6 节旧“旧请求一律核清/全部未解决工作清零”及第 8 节第 4 项中**不可枚举的旧内存请求**部分。已知持久工作、已知外部动作、支付、旧源归属、写入隔离与普通升级要求均不放宽。原 Task 4 BASE 和已完成模块不重置；实现只接原闭环，非本节内容继续按原批准设计执行。

## 2. 路径选择

| 路径 | 代价与限制 | 结论 |
| --- | --- | --- |
| 一次性受控停机引导，接入现有维护机制 | 要核清旧工作和支付，首次需要运维配合；不要求旧进程支持新协议 | 采用 |
| 先给旧版本补维护协议，再升级候选 | 多一次生产代码发布和兼容验证，仍需处理首次协议引导 | 本轮不采用 |
| 新增持久支付回调收件箱后再切换 | 可以降低对外部重投的依赖，但涉及支付持久化及重复处理语义 | 不作为本次前置扩建 |

普通升级仍走现有排空协议。首次引导必须显式选择，绝不在普通升级检查失败后自动降级进入。

## 3. 已知阻塞如何收口

- 旧版运行于 `/opt/holaday-monorepo`，没有维护状态，不能构造假的旧 bootId 或 idle 回执。
- 1 条约 93 天未更新的 running 任务：核对执行归属和外部副作用。年龄、无监听或进程退出均不能单独证明任务成功/失败。现有任务检查仍拒绝未解决的活动记录；如需更改记录，须依据既有任务处理流程单独明确对象、理由和授权，不放进部署脚本自动修复。
- 2 个未来计划及注销 worker：列入所有工作生产者清单；切换前停止新增派发，停止后复核数据库，不能只依据当时 due=0。
- 国内支付 4011 旧实例：先核对进程树、启动来源、入口路由及实际责任。若有生产职责则纳入停机清单；若确认废弃也只能在明确批准其精确对象后停止。未核清则不切换。
- 13 条历史 pending 支付：逐条核对支付方状态及本地结算，不以年龄删除或假定未付款。不要求简单地把 pending 数量改成零。
- 备份和目标配置未验收：分别补真实恢复证据和配置摘要，不能仅记录“已备份/已确认”。

上述数量只描述历史快照。正式检查要覆盖最新集合及核查期间新增记录。

## 4. 最小实现结构

仅增加三个有边界的职责，不再造部署或支付框架：

1. **首次引导协调器**：识别旧版实际进程、关闭入口、停止工作生产者、确认物理退出、准备首次维护状态。只接受批准清单内的对象。
2. **支付与外部写入检查器**：只读收集网关、路由、支付状态与重投演练证据，为现有 readiness 提供可通过也可拒绝的真实检查。
3. **现有发布流程的复用接口**：首次引导达到“旧实例已停止、外部写入已隔离”后，复用候选安装、迁移、关闭启动、验证、开放及 worker 恢复。必要时抽取小范围共用函数，不复制整个 host 流程。

保留普通发布对 `/opt/holaday-releases/<SHA>`、旧身份、排空回执及进程 UID 的严格检查。旧路径识别只存在于首次引导适配器，不放宽普通停止函数。

首次引导使用独立的操作记录类型：包含 attempt、旧源码摘要、实际进程身份、入口清单、候选 SHA、配置及迁移摘要、阶段。不得为了套用现有 journal 的 oldIdentity 参数而伪造旧协议身份。两条路径共用主机级互斥，不能同时启动；残留锁或不确定阶段不自动清除。

## 5. 支付放行条件

### 5.1 保留既有处理语义

沿用微信/支付宝验签后 await confirm/confirmPartner、成功才应答成功的代码；桥接失败保持非成功。PayPal 也不得在未确认处理完成时提前成功应答。不能把日志当作持久化队列。

关闭新订单入口后，准备阶段可继续让已有合法回调结算；进入一致性备份和迁移前，再隔离全部业务写入。隔离覆盖公开和内部路由、WS、网关转发、调度及独立 worker，而非只隐藏前端按钮。维护响应须明确失败/稍后重试，不能被代理缓存改写成成功。

外部支付方重投有界。PayPal 官方说明失败通知最多重试 25 次、持续 3 天，但这不证明现有旧订单仍在重投窗口内。[官方说明](https://developer.paypal.com/api/rest/webhooks/rest/)

微信/支付宝必须核对当前商户实际使用产品的通知策略并取得匹配配置的测试证据；缺少文档或实测时保留阻塞，不使用源码注释推断无限重试。

### 5.2 历史记录与窗口期间支付

只读核对支付方控制台或查询接口，不调用创建、扣款、capture、退款接口来“检查状态”。现有 SDK 没有纯查询入口时，可补窄范围只读核查适配器，不能借用会执行 capture 的函数。

每条记录要归入：已结算且双方一致、支付方已关闭/失败、尚未付款且有效、已付款但本地未结算、状态不明。后两类在切换前必须解决或停止切换；涉及补结算时使用现有幂等路径并另行明确授权，不直接 SQL 改为 completed。

仍有效的未付款订单可能在维护期间付款，必须纳入窗口后的逐条复核清单。清单只用于核对，不替代支付方事件或形成第二套结算队列。新事件、重复事件和延迟事件继续遵守原有验签与幂等逻辑。

切换清单必须给出绝对的维护截止时间、实际负责核对者及补核对截止时间。窗口须落在已证实的通知重投余量内；不能用历史 pending 的创建时间推断通知余量。无法确定剩余重投时，需有经过验证的独立查询及现有补结算路径，否则不切换。

### 5.3 readiness 不接受人工布尔放行

替换当前无条件拒绝的 `checkMaintenanceServices()`，但不增加 `PAYMENT_VERIFIED=true` 等绕过项。检查分两个时点：

- **准备检查**：核实候选/配置/迁移绑定、网关及入口实际职责、历史支付核对结果、重投或查询补核对能力、维护窗口。此时不要求尚未产生的新 bootId，也不假装旧版支持维护 API。
- **开放前检查**：在准备证据基础上，复核隔离仍有效、旧进程未回生、网关路由与配置未变、当前候选关闭状态与真实 bootId、schema/记录检查。

由有权限的主机检查器采集事实，绑定本次 attempt 和现有发布记录，向应用暴露最小脱敏报告。应用不持有 SSH 凭据或商户查询密钥。报告由 root 持有且应用只读，单链接、无符号链接、固定规范路径、限长并严格校验结构；原始私密证据单独保留。

报告需要记录来源、观测时间、目标身份、摘要和实际检查结果，不能只有签名或“成功”字样。动态主机/路由观测开放前重采，报告有效期最多 60 秒，过期、时钟倒退、目标变化均拒绝。支付演练属于绑定代码/配置的历史证据，单独标明日期，不能假装它在 60 秒内发生。

主机检查器在调用 open 前最后复核；报告是受信主机的观察记录，不宣称能抵抗 root 被攻陷或消除所有时间差。隔离状态必须持续保持到精确实例 open 确认后。

## 6. 首次切换顺序

| 阶段 | 必须成立的事实 | 失败处理 |
| --- | --- | --- |
| 离线准备 | 候选/全部配置和 SQL 摘要固定，构建及演练完成；核清旧职责与历史记录；批准维护清单 | 不触碰生产运行状态 |
| 关闭入口 | 新任务/订单不能进入；调度及独立生产者已停；记录在途请求与外部工作 | 不以 HTTP 数量或数据库计数假定全部排空 |
| 旧版退出 | 按 PID、启动时间、UID、exe、cwd 精确停止批准对象；禁用其自动重启；端口、进程树及管理器状态复核 | 拒绝广域 kill 或清理无关进程；仅批准的首次 PM2 定向停止允许其超时 SIGKILL，其他路径仍禁止 |
| 一致性备份 | 全部相关写入隔离；数据库快照与配置/源版本对应；新鲜备份在隔离 MySQL 恢复并核对 | 不执行迁移；不能把旧备份存在当作当前恢复证明 |
| 迁移与状态引导 | 持久记录 migration_started 后执行批准的完整迁移清单；首次状态只在严格前提满足后初始化 | 不自动重跑 SQL、不回启旧代码 |
| 候选关闭启动 | 正确 UID/权限；真实新 bootId；closed 且无需 reconciliation；原任务与历史数据检查通过 | 保持关闭，不重置 dirty 状态 |
| 开放 | 支付与外部服务检查通过；确认同一候选实例 open；再开放相应外部入口并恢复 worker | 丢失 ACK 只查询同实例状态，不盲目重试或重启 |
| 开放后核对 | 实际回调恢复、窗口支付核对、任务与浏览器探针、进程持久化配置符合清单 | 重新关闭接单并处理本次已有工作，不自动回滚数据库 |

旧版没有全量排空协议，因此“可停机”不是“可丢弃在途工作”。旧请求/外部工作无法核清时停止切换；确需中断具体任务时单独列出后果取得授权，未知副作用仍不能变成新实例 clean 的依据。

首次状态仅允许在目标状态目录及锁均不存在、旧实例实际退出、写入隔离且未解决工作已清零后创建。目录属应用 UID、0700，状态文件 0600；初始化身份明确为引导种子，不冒充旧实例。候选启动生成不同的真实 bootId。若发现既有状态、dirty 或残留锁，进入人工核对，不覆盖初始化。

当前 runner 会处理全部 61 个编号 SQL，0042 涉及支付完成时间更新。上线批准必须覆盖完整迁移清单及 runner 摘要，并在恢复库验证历史字段变化符合已批准预期；不是只批准新增字段就执行整套。若存在不可接受的数据变化，停止并另提最小迁移修正，不夹带执行。

不新增“仅支付开放”运行模式。现有 open 会允许内部生产者工作，故开放前必须满足完整 readiness；不能安排“先开放支付完成结算，再满足 open 条件”的循环依赖。维护期间新发生的支付在开放后按既定重投/查询路径核对，不宣称开放前已经收到未来回调。

## 7. 失败与恢复

- 每次有副作用的操作前持久记录阶段，SSH 中断只读确认记录及实际进程，不按客户端超时认定远端未执行。
- 候选启动后失败保持 closed；迁移开始后不自动回启旧代码或恢复旧数据库，避免覆盖外部支付事实。
- 截止时间到达时停止新增不可逆步骤，保持维护并明确告警与支付核对责任。截止时间不是强制开放或强制回滚开关。
- 备份恢复只先在隔离数据库演练。真实生产恢复涉及窗口期间支付及其他外部副作用，必须另行制定并批准恢复清单。
- 首次成功后禁用首次引导入口的适用条件；后续部署只使用已建立的普通维护协议。

## 8. 固定验收范围

下一阶段实施计划只围绕以下验收，不因发现旁支需求追加功能：

1. 普通维护回归不变；旧路径不能通过普通运行时校验；普通失败不能自动进入首次引导。
2. 首次引导和普通发布互斥；模拟重复启动、锁残留、状态已有/dirty，均无覆盖或绕过。
3. 隔离 Linux 实际进程验证旧 cwd、UID、PID 重用、自动重启、端口残留、worker 和未知同目录进程；不只 mock 物理退出。
4. 活动任务、外部效果不明、未来派发未停、4011 职责未明时拒绝；无隐式任务/订单改状态。
5. 隔离 MySQL 从新鲜样本备份恢复后跑完整 SQL，核对数据保留和 0042 的已批准行为；迁移中断不自动重跑。
6. readiness 证明缺失、来源不匹配、配置漂移、错误 bootId、过期、符号链接、错误所有权、超长数据均拒绝。
7. 网关桥接失败不应答成功；恢复重投、重复/乱序事件保持幂等，不重复发权益。覆盖现有普通订单与 partner 支付分支。
8. 支付方真实测试环境验证实际验签及重投，记录测试与生产配置差异。PayPal 模拟器 mock 不支持当前使用的远程验签路径，须使用真实 sandbox 应用事件，不能为通过测试降低验签。[官方说明](https://developer.paypal.com/api/rest/webhooks/rest/)
9. 首次从停止旧版到候选关闭启动、精确开放、恢复 worker 的完整演练；open ACK 丢失及各阶段中断不误开、不自动回滚。
10. 开放后维护窗口支付复核及浏览器最小任务探针有明确结果；代码部署成功不等于浏览器成功率全面达标。

没有支付方测试权限、可靠查询或旧任务处理依据时，报告外部阻塞与下一项具体动作，不把 mock 测试计作生产验收。
