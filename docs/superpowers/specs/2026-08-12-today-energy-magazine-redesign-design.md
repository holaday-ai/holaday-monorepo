# HOLA DAY 今日能量「能量杂志」改版设计

## 1. 决策与问题修正

本轮采用用户确认的 A 方案「能量杂志」，重做 `/cosmic` 页面下半部分。目标不是给现有文字卡片继续添加颜色或小图标，而是把浏览体验改成由图片建立兴趣、短文案辅助判断、点击后再阅读或互动的轻内容杂志。

当前线上版本未达到该目标，根因已经确认：

- `EnergyExploreFeed` 只给每批前两条内容渲染图片，后四条被明确渲染为图标卡；
- 星座知识统一使用当前星座徽章作为主图，因此同一批中会出现两张完全相同的星座图；
- 卡面持续展示类别、时长、标题、摘要和操作文案，图片只成为文字上方的装饰；
- 星座六维和“继续往下逛”仍采用同构文字单元，页面整体节奏没有从信息面板切换到休闲浏览。

新版必须从组件结构和视觉分配规则上修正这些问题，不能只替换 CSS 或增加图片数量。

## 2. 范围与非目标

本轮重做以下区域：

1. 星座深度补给站的首屏表达、六维入口与幸运线索；
2. 星座区内的四个继续探索入口；
3. 页面底部“再逛一会”的六条内容；
4. 上述区域使用的静态插画资产、映射规则和换组反馈。

必须保留：

- DivineAPI 与现有本地降级数据流；
- 今日、本周、本月、本年的周期切换；
- 六维内容、幸运色、顺手时段、七日趋势和诚实空态；
- 十二星座排行、换星座、抽卡、轻测试和小游戏的现有目标；
- 每组六条内容、会话内去重、浏览进度和既有事件上报；
- 现有键盘操作、焦点恢复、语义标签和减少动态效果支持。

本轮不做：

- 不修改页面上半部分的主能量英雄区和三种主要玩法入口；
- 不新增 API、数据库、内容后台、积分或广告逻辑；
- 不伪造 Provider 数据或扩大 DivineAPI 能力声明；
- 不重构抽卡、测试和小游戏内部玩法；
- 不在运行时调用图片生成服务，插画以构建时静态资产交付。

## 3. 页面信息架构

### 3.1 星座专刊封面

“星座深度补给站”改为一张横向专刊封面：

- 当前星座的马卡龙徽章只作为该区域主视觉出现一次；
- 标题、周期和一句核心摘要与主图共同构成封面；
- 幸运色、顺手时段和数据周期显示为三个短信息泡泡；
- Provider 来源和降级状态保留，但放在封面底部的低噪声来源行；
- 主图必须完整展示，不允许裁掉星座主体。

六维内容不再默认铺开为三至六张长文字卡。默认展示三张“栏目预告”：每张使用独立的 3D 主题小景，只显示维度名称和一句短摘。点击后在原区域内展开完整文本；“展开全部六项”继续保留，但展开后仍采用图文交替布局，而不是恢复成纯文字网格。

### 3.2 四个杂志栏目入口

原“继续往下逛”四个横向文字按钮改为四个圆形封面入口：

1. 十二星座排行：十二徽章环绕的星轨场景；
2. 换个星座看看：星盘切换场景；
3. 抽一张相关能量牌：塔罗牌场景；
4. 测个相关主题：心情实验场景。

每个入口以图片为主体，标签和一句短提示放在图片下方。桌面端横向排列，手机端保持可滑动横排，避免四张入口再次变成长文字单列。

### 3.3 “再逛一会”六条内容

每批仍严格展示六条内容，但改为杂志版式：

- 第 1 条：横跨两列的大幅主故事；
- 第 2、3 条：两张竖向封面；
- 第 4、5、6 条：三张横向图片短篇。

六张卡全部必须有图片，不再存在 `compact` 图标卡。卡面只展示类别、预计时长、标题和最多一句摘要；完整文本通过点击现有内容目标后展示。

主故事允许在图片上使用可读的渐变遮罩和标题。其余卡片以图片区和简短标题区为主，不能让正文高度超过图片区。布局通过 CSS Grid 的明确槽位实现，内容顺序仍由现有推荐结果决定。

## 4. 插画资产与唯一性规则

新增约 12–16 张同风格静态插画，延续现有明亮马卡龙、柔和 3D、圆润材质和轻松场景语言。资产至少覆盖：

- 放松与呼吸两种场景；
- 幸运签与幸运胶囊两种场景；
- 抽卡与三牌阵两种场景；
- 情绪测试与关系测试两种场景；
- 小游戏与能量收集两种场景；
- 星座知识与星盘探索两种场景；
- 投票和关系问答等补充场景。

现有十二星座徽章继续用于星座专刊封面和小型角标。星座知识卡不再直接把当前星座徽章当作整张主图，而是使用知识类场景图，并叠加当前星座小角标，从结构上消除重复狮子图的问题。

新增 `magazineVisualFor(item, slot, zodiacSign)` 视觉分配层：

- 先按内容类别选择图片家族；
- 再根据稳定内容 ID 选择家族内变体；
- 批次分配器检查六个结果，若重复则使用该家族下一变体；
- 同一批六条内容不得出现相同 `imageSrc`；
- 图片分配不改变推荐、去重和业务排序。

交付资产优先使用 WebP；单张目标不超过 180 KB，主故事不超过 260 KB。保留 JPEG 降级只用于现有历史资产。所有图片声明宽高或固定 `aspect-ratio`，防止加载时布局跳动。

## 5. 内容与状态流

现有 `nextEnergyContentBatch` 继续只负责选择六条内容。选中结果进入展示层后，新的批次视觉分配器为每条内容补充：

- `layoutSlot`：hero、portrait 或 landscape；
- `imageSrc`：本批唯一的静态插画；
- `tone`：与类别匹配的马卡龙语义色；
- `badge`：可选的当前星座角标；
- `fallbackIcon`：图片失败时使用的语义图标。

换组时仍保存已看内容 ID，并保持已有事件 `energy_feed_refreshed`。视觉分配只依赖当前六条结果和稳定 ID，不进入持久化，不影响历史去重。

打开内容时继续触发 `energy_content_opened` 和原有 `actionTarget`。卡片自身只增加已读蒙层、完成标记和轻微色彩变化，不创建第二套打开逻辑。

## 6. 组件边界

定向修改以下组件：

- `AstrologyWorld.tsx`：星座专刊封面、来源行和四个图片栏目入口；
- `AstrologyDimensionGrid.tsx`：三张栏目预告、展开后的图文条目和焦点行为；
- `LuckyInsights.tsx`：将幸运色与时段收进封面信息泡泡，同时保留趋势数据；
- `EnergyExploreFeed.tsx`：六个全图片槽位、批次唯一图片分配和已读反馈；
- `energy-visuals.ts`：视觉家族、稳定变体和批次去重逻辑；
- `energy.css`：杂志 Grid、封面遮罩、横向栏目、响应式与动效；
- `public/energy/magazine/`：新增经过压缩的静态插画。

如果单个组件因新版结构超过现有可读边界，则抽取纯展示组件 `EnergyMagazineCard` 和 `AstrologyMagazineCover`。页面级状态继续留在现有拥有者中，不新增全局 store。

## 7. 交互与动效

- 专刊封面主图使用 7–10 秒的轻微漂浮，位移不超过 6px；
- 栏目封面悬停上浮不超过 3px，图片缩放不超过 1.025；
- “再来一组”使用 220–300ms 的淡出、换组和交错淡入；
- 主故事进入时允许轻微遮罩提亮，不能循环闪烁；
- 已读状态同时使用勾选图标、短文案和背景变化，不能只依赖颜色；
- 所有可点击封面保持原生按钮语义，触控目标不少于 44×44px；
- `prefers-reduced-motion: reduce` 下关闭漂浮、缩放和交错动画。

## 8. 响应式行为

桌面宽度下使用四列杂志 Grid：第一行由横跨两列的主故事和两张单列竖向封面组成，第二行三张横向短篇等宽排列。中等宽度改为两列，主故事横跨两列。手机宽度下：

- 专刊封面改为文字在上、完整图片在下；
- 四个栏目入口使用横向滚动，不压缩成过窄四列；
- 六条内容改为单列，但主故事、竖向封面和横向短篇仍通过不同图片比例保持节奏；
- 任何宽度都不得出现水平页面溢出；
- 星座徽章和单主体资产使用 `object-fit: contain`；场景插画使用 `cover`，并在视觉元数据中为每张图声明经过浏览器验收的 `object-position`，不得裁掉主要角色。

## 9. 错误、性能与可访问性

- 图片加载失败时隐藏失败图片，显示同色底、语义图标和原有可操作内容；
- Provider 失败继续使用现有本地降级提示，不用插画掩盖数据缺失；
- 六条内容为空时保留真实“本次已看完”空态；
- 图片使用原生延迟加载；首个可见主故事可优先加载，其余图片延迟加载；
- 装饰图片使用空 `alt`，承载内容意义的封面提供与标题不重复的简短替代文本；
- 渐变遮罩上的文字必须通过对比度检查；
- 键盘焦点样式、`aria-label` 和原生 `title` 继续满足现有控制提示测试。

## 10. 验收标准

自动验证：

1. 每批仍为六条内容，换组与去重逻辑不变；
2. 六张卡全部渲染图片容器；
3. 同一批六个 `imageSrc` 唯一；
4. 两条星座知识不会渲染两张相同星座主图；
5. 图片失败后图标兜底和按钮仍可使用；
6. 内容打开和四个栏目入口继续触发原目标；
7. 能量域测试、Web Workbench 全量测试、lint、typecheck、build 和 `git diff --check` 通过。

浏览器验证：

1. 桌面端下半页第一眼由图片和封面建立层级，而非文字网格；
2. 星座主图完整且只作为主视觉出现一次；
3. 六张内容图不重复，类别和图片含义匹配；
4. 换组后内容与图片共同替换，无闪白和旧图残留；
5. 至少打开一张主故事、一张竖向封面和一张横向短篇；
6. 四个栏目入口全部可进入原有目标并正确恢复焦点；
7. 390px 手机宽度无横向页面溢出、图片主体裁切或小于 44px 的操作目标；
8. 控制台无相关错误和警告；
9. 减少动态效果设置下没有持续动画。

## 11. 交付与上线边界

本轮实施形成独立前端分支和 PR。提交前提供新增资产清单、文件体积、自动验证结果和桌面/移动浏览器证据。PR Ready、合并和生产部署继续分别等待明确授权；设计确认本身不授权合并或部署。
