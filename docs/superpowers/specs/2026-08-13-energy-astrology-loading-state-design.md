# HOLA DAY 星座内容可信加载态设计

## 1. 背景与根因

`/cosmic` 的 DivineAPI 日运和周运请求在页面挂载后异步发起。当前 `useEnergyAstrology()` 在请求开始前就把本地备用内容作为已加载状态暴露给界面，请求期间只将 `loading` 改为 `true`，但仍保留 `source: 'local-fallback'`。因此顶部星座卡、星座专刊和星座深度补给会在真实数据返回前短暂显示“本地备用提示”，造成供应商配置失败的错觉。

这不是 DivineAPI 请求失败，而是“尚未得到结果”与“请求失败后回退”共用了同一个展示状态。

## 2. 目标

- 首次真实供应商请求期间不展示本地备用文案、数值或来源标签。
- 以保持原有马卡龙布局的柔和骨架表达“正在读取星座能量”。
- 只有请求确实失败或服务端明确返回本地回退时，才展示本地内容和低噪提示。
- 已有成功内容的手动刷新采用 stale-while-revalidate：保留旧内容，只显示刷新进行中状态。
- 顶部星座卡、星座专刊、日/周/月/年面板和星座深度补给使用一致的状态语义。

## 3. 状态模型

每个周期继续使用 `loading`、`loaded`、`source` 和 `error`，但明确其含义：

- `loading=true, loaded=false`：首次请求，界面显示骨架；
- `loading=false, loaded=true, source='divineapi'`：供应商内容可见；
- `loading=false, loaded=true, source='local-fallback'`：请求已经结束且回退，本地内容与提示可见；
- `loading=true, loaded=true`：对已解析内容进行刷新，旧内容保持可见，刷新按钮进入忙碌状态。

`useEnergyAstrology()` 首次渲染时就将自动加载的日运、周运设为 `loading=true, loaded=false`，不能等到 `useEffect` 后才切换，否则仍可能产生一帧备用内容闪烁。月运和年运保持按需加载，首次选择对应周期时进入相同骨架状态。

整体状态增加只读的 `initialLoading`，由日运和周运是否存在 `loading=true, loaded=false` 推导。它只用于组合型顶部卡和深度补给；周期专刊直接依据当前周期状态判断。

## 4. 界面行为

### 4.1 顶部星座能量卡

- 保留星座插画、区域标题和操作区，避免布局跳动。
- 首次加载时将能量值、标题、摘要和两条周运内容替换为马卡龙渐变骨架。
- 使用 `aria-busy="true"`，并提供屏幕阅读器可读的“正在读取星座能量”。
- 不把本地备用标题、正文和“本地备用提示”放入可见或无障碍文本树。

### 4.2 星座专刊与周期面板

- 专刊保留星座插画和四周期 Tab；摘要、来源、幸运色、顺手时段与范围使用骨架。
- 当前周期首次加载时，维度网格和幸运信息由保持高度的骨架替代。
- 首次加载完成后再决定显示 DivineAPI 来源或本地回退提示。
- 切换到尚未请求的月运/年运时使用同一骨架；切回已有内容不重复清空。

### 4.3 星座深度补给

- 用户在首次请求期间打开弹层时，显示专用加载卡，不显示本地日运和周运。
- 加载完成后原位切换为真实内容；失败时显示现有低噪备用提示。

### 4.4 手动刷新

- 已成功加载时保留当前内容和尺寸。
- 刷新按钮禁用并旋转，区域设置 `aria-busy="true"`。
- 刷新失败后显示本地回退或最近成功数据，具体取决于现有请求返回；不得短暂切换为首次骨架。

## 5. 视觉与动效

- 复用现有薰衣草、蜜桃、薄荷和天蓝马卡龙色，不加入灰黑色大面积占位。
- 骨架使用低对比渐变扫光，周期约 1.6 秒，边角与被替换内容一致。
- `prefers-reduced-motion: reduce` 下取消扫光位移，只保留静态柔和底色。
- 骨架固定最小高度，避免内容替换造成累计布局偏移。

## 6. 测试与验收

自动化测试必须证明：

1. 真实供应商首次请求尚未结束时，日运/周运是 `loading=true, loaded=false`；
2. 顶部卡、专刊和深度补给不显示备用标签或本地正文，只显示加载提示；
3. 请求失败后才显示本地内容和备用提示；
4. 成功内容刷新时 `loaded` 保持为 `true`，旧正文仍可见；
5. 月运/年运首次选择显示周期骨架；
6. 减少动态效果时骨架动画被关闭；
7. 今日能量目标测试、类型检查和生产构建无回归。

浏览器验收覆盖桌面与 390px 移动视口，使用延迟请求或网络节流确认首次加载、成功替换、失败回退和二次刷新四种状态。
