## 批量 Confirm 协议（端到端）

### Server → Client（新）

```
{
  "type": "server.batch_confirm_required",
  "taskId": "tsk_…",
  "stepId": "stp_…",
  "batchIndex": 1,          # 0-based
  "batchTotal": 4,
  "summary": "批次 2/4：3 星及以下，共 5 条未回复",
  "items": [
    { "label": "@买家 · ★1 · 2h", "preview": "商品发霉了…\n—\n草稿：非常抱歉…", "meta": { "commentId": "c_xxx" } }
  ],
  "risk": "high"
}
```

### Client → Server

经 tRPC `POST /trpc/tasks.confirm`：

```json
{ "taskId": "tsk_…", "decision": "approve" | "skip" | "reject" }
```

旧 `{approve: boolean}` 兜底保留（popup v0 迁移窗口）。

### TaskController 状态迁移

| 前置 | decision | 后置 | WS broadcast |
|---|---|---|---|
| awaiting_user (batch) | approve | executing（cursor 不动） | server.task.dispatch 重发当前步 |
| awaiting_user (batch) | skip | executing（cursor+1） | server.task.dispatch 下一步 |
| awaiting_user (batch) | reject | cancelled | server.task.control cancel |
| awaiting_user (single) | approve / skip | executing（cursor+1） | server.task.dispatch 下一步 |
| awaiting_user (single) | reject | cancelled | server.task.control cancel |

### TaskRepository 分支

| 过渡 | 方法 |
|---|---|
| reject → cancelled | `applyControlTransition`（`task.cancelled` 事件） |
| **batch + approve**（新） | `applyBatchApprove`（清 pending_confirm_payload，step 回 executing，cursor 不动，`batch.approved` 事件） |
| skip / single approve | `applyStepResult`（cursor 前进，step 标 completed） |

### 重启恢复

`applyRehydrationForUser` 按 `pendingConfirm.kind` 重发：
- `kind: 'batch'` → `server.batch_confirm_required`（items/index/total/summary 全保留）
- `kind: 'single'` → `server.user.confirm`
- 旧的 flat `{stepId, prompt, risk}` 行自动 upgrade 成 `kind: 'single'`（不破坏 pre-batch 任务）

## `douyin-comment-manager` Skill 要点

第一个**写场景** Skill，安全边界写在 manifest caveats：

- 读（extract / scroll / filter / screenshot 审计）：`risk: low`
- 写（reply / pin / delete / hide）：`risk: high`，强制每批 awaiting_user
- **Skill 层硬禁止**：删差评 / 屏蔽差评 / 引导好评（"好评返现"等促销诱导）

## 踩坑 & 处理

1. **MariaDB JSON 列在 applyBatchApprove 里没坑**：只写 status + pending_confirm_payload=null，没遇到 MariaDB LONGTEXT 反序列化问题。rehydrate 继续用 `normalizeJson` 兜 legacy 格式。
2. **YAML 解析 SKILL.md frontmatter**：`contenteditable` 等英文短串里出现 `<` 和反引号时 js-yaml 抛 `bad indentation`——caveats / hints 里所有带特殊字符的行用**双引号**包起来就过了。这是 Skill 作者需要留心的隐性约定；未来 W3 如果给运营/非工程人员手写 SKILL.md，考虑在 `packages/skill-sdk` 加一个 pre-commit 校验。
3. **step 状态的语义**：batch approve 时 step **不能**标 `completed`（否则下次 extension 再发 step.result 就找不到 current 了）。我最初的 applyBatchApprove 忘了改 step 状态，集成测试直接揪出来——现在统一 `step.status='executing'`。
