## 关键实现要点

### `packages/browser-driver/` 分层

```
driver.ts          HolaDayBrowserDriver 接口 + DriverAction + DriverResult + DRIVER_ERRORS
selector-plan.ts   ResilientSelector → LocatorSpec[]（纯数据翻译，无 Playwright 依赖）
origin-guard.ts    isOriginAllowed(url, allowedOrigins[])：bare / *.sub / host:port
mock.ts            MockDriver（测试 + headless fallback）
crx-adapter.ts     PlaywrightCrxAdapter（只有 extension SW 加载）
```

刻意把 SelectorPlan 和 OriginGuard 做成**纯数据层**：
- 单测不需要浏览器
- W1 bug #3 的"Opus 产不完整 selector"回归用 `buildSelectorPlan` 跳过 malformed strategy 3 行代码兜住，测试覆盖（`skips malformed strategies instead of throwing`）
- 防 lookalike 攻击：`isOriginAllowed('https://evilexample.com', ['*.example.com']) === false`（有专门的测试）

### PlaywrightCrxAdapter 设计

- Lazy 启动：`crx.start()` 延迟到第一次 `execute()`，第一次 `goto` 时 `app.newPage({url})` 或 `app.attach(tabId)`。
- 每步 resolve selector：按 `SelectorPlan.attempts` 顺序用 `locator.first().waitFor({state:'attached', timeout: 2s})`，第一个返回的就用。
- 7 个 kind 对应 7 个私有方法，错误分类用 `DRIVER_ERRORS` 常量：
  - goto: `NAV_FAILED` / `ORIGIN_BLOCKED`
  - click: `CLICK_FAILED` / `SELECTOR_NOT_FOUND` / `SELECTOR_MISSING`
  - type: `TYPE_FAILED` / `PAYLOAD_MISSING` (也 handle contenteditable: fill fail → focus+keyboard.type fallback；Douyin 回评框 SKILL.md 已警告)
  - extract: 有 selector → innerText 列表（≤ 50）；无 selector → 返回 `{url, title}`
  - eval: 执行 `payload.expression`；W3 SafetyFilter 会把这条锁白名单
  - screenshot: `page.screenshot({type:'png', fullPage?})` 返回 base64 bytes 数字，**不** 直接发 WS（太大），等 W3 S3 上传路径
  - wait: selector 存在 → waitFor；无 selector → payload.ms（cap 30s）
- `dispose()` 调用 `app.close()`，释放 `chrome.debugger`。

### SW 集成

- `chrome.debugger` permission 加到 manifest。Chrome 会横条显示"HOLA DAY 正在调试此浏览器" —— 这是用户看得到的"Agent 在真驾驶"的视觉标志。
- `getDriver()` 在 SW 第一次 dispatch 时触发：capability 检查 `chrome.debugger && chrome.tabs`，真 SW 里 dynamic import CRX adapter；否则（build-on-Linux / 沙箱）返回 MockDriver(autoAckDelayMs=200)——保留 Agent Loop 的可演示性。
- `runStep(msg)` 翻译：action → driver.execute → result → `client.step.result`。`DRIVER_CRASH` fallback 捕获 driver 本身抛错（例如 chrome.debugger 被用户取消授权）。
- step view 状态跟随驱动回报：`ok` → completed，`awaiting_user` → awaiting_user（支持 Skill 的登录检测 pattern），`error` → failed。

### 安全 / 合规微点

- **skill `allowedOrigins` 现在**会被 adapter 硬检查**——传给 `PlaywrightCrxAdapterOptions.allowedOrigins`（今天还没从 orchestrator 传下来；W3 SafetyFilter 那条线接起来）。
- `eval` 步骤有显式注释 "W3 SafetyFilter will wrap this with an allowlist"。Phase 0 先过 tainted-but-functional。
- Debugger banner 对用户是明示："这个扩展正在控制你的浏览器"。不做静默接入。

## 风险 / 需要决策

- ⚠️ **真机跑出 blocker 的优先级**：你跑 `docs/W2_BROWSER_DRIVER_GUIDE.md` 发现问题 → 截图 + SW console 日志发回来，我 Day 5 一开始先修。不硬冲是 Day 4 共识。
- ⚠️ **Playwright-CRX 依赖了 Playwright 内部 types（`getByRole` 的 first arg 我用了 `Parameters<...>[0]` 强拿）**：这个 API 在 CRX 包里 re-export，和主 Playwright 类型完全同步。大概率不会坏；真坏了是 Day 5 改 2-3 个类型。
- ⚠️ **3 MB crx-adapter chunk**：Chrome 扩展对 SW 脚本大小没硬限制（MV3 灵活），但加载延迟 50-200ms。只在第一次 dispatch 时 lazy load，用户感知不到。压缩后 842 KB gzip 完全可接受。
- ⚠️ **`chrome.debugger` 的用户感知**：横条"HOLA DAY 正在调试此浏览器"没法关，这是 Chrome 出于安全强制显示。Phase 0 dogfood 阶段要和用户讲清楚"这是 feature not bug"。W3 UX 可以在 popup 里加一段说明文。
