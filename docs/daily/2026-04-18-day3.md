## 关键实现要点

### Commander（`apps/orchestrator/src/agent/planner*.ts`）
- `Planner` 接口：`plan(ctx) -> PlannedStep[]`。
- `StubPlanner`：确定性，测试 + 无 Anthropic key 的本地开发兜底。
- `AnthropicPlanner`：
  - `model = claude-opus-4-7`，`thinking: {type: 'adaptive'}`（Opus 4.7 只支持 adaptive；不带 temperature/top_p/top_k/budget_tokens）。
  - `tool_choice: {type: 'tool', name: 'emit_plan'}` 强制结构化输出。
  - System prompt 上挂 `cache_control: { type: 'ephemeral' }` → prefix-cache 命中。
  - `zod.safeParse` 校验模型返回；`PlannerError(NO_TOOL_USE | INVALID_PLAN)` 可被 tRPC 转 5xx。
- Boot 时根据 `ANTHROPIC_API_KEY` 自动选择 Anthropic / Stub；tRPC context 注入，测试可替身。

### 持久化（`apps/orchestrator/src/agent/task-repository.ts`）
- `insertTask(state, {userId, intent})`：事务内 INSERT `tasks` + 每个 `task_steps` 行（cursor 所在步标 executing）+ 一条 `task.created` 的 `task_events`。
- `applyStepResult(prev, next, payload)`：事务内 UPDATE `tasks.status`（terminal 状态顺手写 `completedAt` / `errorCode` / `errorMessage`）+ 刚完成的 step 行（completed / failed / awaiting_user + output）+ 新 executing 的 step 行 + 一条事件行（`step.completed` / `step.failed` / `step.awaiting_user` / `task.completed` / `task.cancelled`）。
- TaskController 依然纯函数；repo 是唯一写 MySQL 的点，restart-recovery（W2）只需在重启时用 task_steps 回放出 TaskState，不动 controller。
- WS `runStepResult` 在每条 `persist` effect 上 `await taskRepository.applyStepResult(prev, next, data)`；异常 log 不挂 WS 循环。

### Skill 体系（`packages/skill-sdk/` + `skills/`）
- `skillManifestSchema`（strict zod）：slug kebab-case、semver version、entryUrls、riskFloor、hints、caveats。
- `loadSkillsDir(rootDir)`：递归 walk，跨文件 slug 唯一性校验，fail-fast。
- `apps/orchestrator/src/skills/registry.ts::syncSkills(db, dir)`：外部 id 是 sha256(slug@version)[:21] 前缀 `skl_`，幂等 UPSERT。
- `scripts/sync-skills.ts`：一次性注册命令，已验证：
  - 第一次：`inserted=1 updated=0`
  - 第二次：`inserted=0 updated=1`
- 首个 skill `taobao-qianniu-inbox@0.1.0` 已落库，`manifest` JSON 字段包含 frontmatter + body，commander 无需再摸文件系统。
