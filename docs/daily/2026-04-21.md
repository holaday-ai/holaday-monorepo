## 关键实现要点

### Extension SW：任务状态 + stub 执行
- 模块级 `tasks: Map<taskId, TaskView>`。
- 接到 `server.task.dispatch` → 写入 step.executing → 500ms 后**自动 ack** `client.step.result status='ok' data:{stub:true, kind}` → step 标 completed。整个 Agent Loop 无需真浏览器动作就能演示。
- 接到 `server.user.confirm` → 设 pendingConfirm + status='awaiting_user'。
- 接到 `server.task.control {pause|resume|cancel}` → 更新 status + pauseReason。
- 每次变更 push `chrome.runtime.sendMessage({type:'holaday.tasks.update', tasks})` 给 popup。
- 真浏览器动作 W2 接 Playwright-CRX 后替换 stub。

### Popup：live 任务卡片 + 控制面
- 登录后多了 intent textarea（默认填"帮我整理今天半导体板块的要闻"） + Run 按钮。
- 一张卡片一 task：step 列表逐行高亮当前，顶部 status badge 彩色（executing 蓝 / awaiting_user 黄 / paused 橙 / completed 绿 / failed 红）。
- `awaiting_user` 状态下弹橙色 confirm box，Confirm/Reject 调 `/trpc/tasks.confirm`。
- `executing` 态下可点 Pause；`paused` 态下可点 Resume；调 `/trpc/tasks.{pause,resume}`。
- 订阅 SW 的 `holaday.tasks.update` 广播，popup 打开期间实时更新。
- Vite 51 modules 构建通过；dist/ 可直接 `chrome://extensions` 加载。

### `tasks.confirm` tRPC
- Input: `{ taskId: string, approve: boolean }`。
- Guard: 412 if `prev.status !== 'awaiting_user'`。
- approve → `controller.userConfirm('approve')` → 走 `applyStepResult`（cursor+1、下一步 executing、广播 dispatch）。
- reject → `controller.userConfirm('reject')` → 走 `applyControlTransition`（status=cancelled、广播 task.control cancel）。
- 集成测试：起一个**临时 Express server** (random port) 跑真 tRPC fetch，验证 approve → 200 `status=executing` + DB 写入、reject → 200 `status=cancelled` + DB 写入。

## Agent Loop 完整闭环（现状）

```
login → create → Opus planning → persist → dispatch
 ↓
  stub step.result ok
 ↓
  [high-risk?] yes → awaiting_user + 弹 confirm box
                      → Confirm → advance → dispatch next
                      → Reject  → cancel
 ↓
  [Pause 按钮]     → paused(user)
                   → Resume → 重发 dispatch
 ↓
  [kill orchestrator]
  ↓
  [restart] → rehydrateInFlight → 重发 confirm / pause 到扩展 → 继续
 ↓
  末步 ok → completed
```

所有 transition 都：
1. 通过 TaskController 纯函数计算 next state
2. 通过 TaskRepository 写事务（tasks + task_steps + task_events）
3. 通过 WS broadcast 推给用户的所有连接
4. popup 订阅广播实时更新 UI
