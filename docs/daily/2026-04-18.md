## 关键实现要点

### Auth 流
- `argon2id`，mem 19 MiB / time 2 / par 1（约 50ms）。
- JWT HS256，issuer `holaday-orchestrator`，audience `holaday-app`，TTL 7 天。
- `bearerAuth` 中间件读 `Authorization: Bearer <jwt>`，写到 `req.userId`，tRPC ctx 直接消费。
- tRPC `auth.register` / `auth.login`：zod 校验邮箱+密码强度，`AuthError` → `CONFLICT` / `UNAUTHORIZED`。

### `apps/extension` MV3 + Vite
- `@crxjs/vite-plugin` 自动产物：`dist/manifest.json` + `dist/service-worker-loader.js`。
- Background SW = 单一 WS 连接，subprotocol `holaday.v1` + `jwt.<token>`，30s ping，断线指数退避（cap 30s + jitter）。
- Popup React：邮箱/密码登录 → POST `/trpc/auth.login` → token 入 `chrome.storage.local` → SW connect → 状态轮询。
- Vite build 验证：42 modules transformed，0.97 KB manifest，OK。

### `TaskController` 状态机
- 纯函数：`start` / `onStepResult` / `userConfirm` / `cancel` 都返回 `(state, effects[])`。
- effects = `send | persist | noop`；persist 在 W2 接 Drizzle，scaffold 期跳过。
- 高危步骤（risk='high'）即使 ok 也会强制 `awaiting_user`，符合设计文档要求。
- WS server 路由 `client.step.result` → `TaskController.onStepResult` → 回 `server.task.dispatch` / `server.user.confirm` / `server.task.control`。

### 集成测试基础设施
- `src/test/db-helper.ts::applyMigrations(databaseUrl)`：跑 `drizzle/0000_initial.sql`，先 FK_OFF→DROP→CREATE，可重入。
- 不应用 `drizzle/manual/000{1,2}` 分区脚本（MariaDB 兼容性）。CI 跑 MySQL 8.4 时再开。
