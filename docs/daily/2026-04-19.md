## 关键实现要点

### Anthropic smoke（Haiku）
- `claude-haiku-4-5`，max_tokens=256，prompt = "Reply with exactly one word: \"ok\". No punctuation, no other text."
- 失败按 `Anthropic.APIError` 类型化，stdout 输出 JSON envelope，`process.exit(1)`。
- 加入 `pnpm --filter @holaday/orchestrator smoke-anthropic` 脚本。Phase 0 不进 CI（要钱），运维手跑。

### `pending_confirm_payload`
- Drizzle schema 加 nullable JSON 列；`drizzle/0001_pending_confirm_payload.sql` 自动生成（`ALTER TABLE task_steps ADD ...`）。
- `TaskRepository.applyStepResult`：transition → `awaiting_user` 时写 `{stepId, prompt, risk}`，其它任何 transition（resume / fail / cancel / next executing）写 `null` 清掉。
- `rehydrateInFlight()`：join `tasks ⨝ users`，读 in-flight 状态（pending/planning/executing/awaiting_user/paused），按 `task_steps.seq` 拉步序，cursor = 第一个非 terminal step。返回 `RehydratedTask[] = {state, userExternalId, pendingConfirm}`。
- 顺手修了 `db-helper.ts`：之前只 apply `0000_initial.sql`，现在按 `\d{4}_*.sql` 全部按序应用，并把整条 chain 的 CREATE TABLE 全部预 DROP，保证 reruns 干净。
- MariaDB 兼容：JSON 列在 MariaDB 上回的是 LONGTEXT 字符串，加了 `normalizeJson` 兜底解析。

### Restart recovery
- `ws/server.ts` 模块级 `rehydratedByUser: Map<string, RehydratedTask[]>`。
- `loadRehydratedTasks()` boot 时调用一次：拉全表 in-flight → 按 user external_id 分桶。
- WS 鉴权成功（subprotocol header 路径 + client.hello fallback 路径都加了）→ `applyRehydrationForUser(state)`：把 task 写进 `state.tasks`，对 `awaiting_user` 的 task 立即 send `server.user.confirm`。然后 `rehydratedByUser.delete(userId)` —— 同一 user 多 tab 重连不会重复弹窗。
- `index.ts` 在 `createWsServer` 之前 await `loadRehydratedTasks()`，启动日志 `{userCount, taskCount}`。
- 集成测试：seed 一条 awaiting_user → fresh server → JWT 客户端连入 → 5 秒内拿到 `server.user.confirm`，taskId/stepId/prompt/risk 全对。

## Agent Loop 现状对照设计文档

设计文档 §四 状态机：

```
pending → planning → executing ↔ awaiting_user
                        ↕           ↓
                      paused    cancelled
                        ↓
                    completed / failed
```

| 路径 | 实现 | 持久化 | 重启恢复 |
|---|---|---|---|
| pending → executing | ✅ TaskController.start | ✅ insertTask | ✅ rehydrateInFlight |
| executing → executing (next) | ✅ onStepResult ok | ✅ applyStepResult | ✅ |
| executing → awaiting_user | ✅ high-risk / requiresConfirm / explicit | ✅ + pending_confirm_payload | ✅ + 重发 server.user.confirm |
| awaiting_user → executing (approve) | ✅ userConfirm('approve') | ✅ 清 pending_confirm_payload | n/a（线上不需要再恢复） |
| awaiting_user → cancelled (reject) | ✅ userConfirm('reject') | ✅ | n/a |
| executing → failed | ✅ onStepResult error | ✅ + errorCode/Message | n/a（terminal） |
| executing → completed | ✅ ok 到末尾 | ✅ + completedAt | n/a |
| paused | ⛔ Phase 0 暂未实现 | ⛔ | ⛔ |
| pending → planning（异步） | 简化为同步 planning（commander 内联） | — | — |

Milestone 1 "Agent Loop 崩溃恢复" 这条线**已可验收**。`paused` 留 Phase 0 后期。
