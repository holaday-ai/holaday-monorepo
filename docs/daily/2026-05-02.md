## 关键实现要点

### `agent/llm-call-recorder.ts` 分层

```
LlmCallRecord          输入记录（userExternalId / model / tokens / purpose / status / ...）
LlmCallRecorder        interface { record(r): Promise<void> }
NoopLlmCallRecorder    测试 + 无 DB 环境
DrizzleLlmCallRecorder 真写入
estimateCostUsd()      纯函数，单测覆盖所有 tier + cache 乘数 + unknown fallback
```

DrizzleImpl 几个关键点：

- `userExternalId → users.id` 解析不到：**silently drop**，`opts.onError` 回调通知调用方。计费失败绝不能杀 Agent Loop（一条行情记不进去 << 整个任务挂掉）。
- `taskExternalId → tasks.id` optional：commander plan 没有 task 上下文时允许为 NULL。
- 所有异常都被 try/catch + `opts.onError(err, call)` 回调。boot 处接 `pino.warn(...'llm_calls INSERT failed (non-fatal)')`。
- 成本：`(inputTokens*inputPrice + outputTokens*outputPrice + cacheRead*input*0.1 + cacheWrite*input*1.25) / 1e6`，`toFixed(6)` 后转 MySQL DECIMAL(10,6)。
- 模型匹配剥 `-YYYYMMDD` 后缀（Anthropic 响应里 model 字段带日期）。未知模型 fallback 到 Opus tier（保守记高，不会低估）。

### `trpc/routers/llm-calls.ts` · `llmCalls.list`

- **Scope**：caller 的 `users.externalId` → internal id → `where(llmCalls.userId = userRow.id)`。绝不能跨用户。Phase 1 admin/org view 单独做。
- Filters：
  - `taskExternalId?` — 解析到 task.id；未知或不归 caller → 返空页（**不 400**，UI 体验更好）。
  - `since?` / `until?` — ISO 时间戳，`gte(createdAt, since) AND lt(createdAt, until)`。
  - `cursor?` — DESC id cursor，上一页最后一行的 id；下一页 `lt(id, cursor)`。
  - `limit` — 默认 50，capped 500。
- **rows 和 totals 分离**：分页不影响 totals。UI 的 "X 次调用 / $Y" header 翻页时不跳动。
- DECIMAL 转 number 在服务端完成（MySQL 驱动返回 string），前端不需要自己 parseFloat。
- totals 用 drizzle `sum()` 聚合 5 个字段 + `count()`。
- `nextCursor = rows.length === limit ? rows[last].id : null`。

### Boot 处接线（`src/index.ts`）

const recorder = new DrizzleLlmCallRecorder(db, {
